## 1. 케이뱅크에 입사를 희망하게 된 이유와 입사 후 이루고 싶은 목표에 대해 구체적으로 작성해주세요. ※케이뱅크의 비전도 좋지만, 입사하신 후에 그리고 계신 본인의 비전을 중심으로 작성해주세요. (최소 500자, 최대 700자 입력가능)

케이뱅크에 입사를 희망하는 이유는 앱이 보조 채널에 머무르지 않고 고객이 은행을 경험하는 중심 채널인 환경에서 개발자로 성장하고 싶기 때문입니다. 이런 관심은 허밍블럭스 프로젝트를 진행하며 더 커졌습니다. 허밍블럭스는 실물 블록을 촬영하면 이를 인식해 음악으로 실행해주는 시각장애인 코딩교육용 앱으로, 블록과 콘텐츠를 기획하고 안드로이드 앱 구현부터 기능 확장, 출시까지 직접 경험했습니다. 이 과정에서 기능 구현만으로는 부족하고, 사용자가 어렵지 않게 이해하며 자연스럽게 이용할 수 있도록 흐름을 설계하는 일이 중요하다는 점을 배웠습니다. 또한 앱 안에서의 작은 불편도 곧바로 사용자 경험에 영향을 준다는 사실을 느꼈고, 서비스 완성도를 높이는 일이 개발자의 중요한 역할이라는 점도 배웠습니다. 앱에서 대부분의 금융 경험이 이뤄지는 케이뱅크는 이런 기준을 더 높은 수준으로 고민할 수 있는 환경이라고 생각했습니다.

입사 후에는 복잡한 금융 기능도 고객이 쉽고 안정적으로 사용할 수 있게 만드는 개발자가 되고 싶습니다. 먼저 케이뱅크의 서비스 구조와 개발 방식을 빠르게 익히고, 맡은 기능을 정확하게 구현하며 기본기를 쌓겠습니다. 이후에는 사용자 불편을 줄이는 개선과 AI 기반 효율화까지 연결하며, 고객이 더 편리하고 완성도 높은 금융 경험을 할 수 있도록 기여하겠습니다. 금융 서비스의 높은 기준도 배우겠습니다.

## 2. 지원한 분야에 관심을 갖게 된 계기와 본인만의 특성/강점을 근거로 지원분야에 적합한 이유에 대해 작성해주세요. ※어떤 커리어, 어떤 직장생활을 꿈꾸며 대학생활을 보내셨나요? 처음부터 케이뱅크가 아니었어도 좋아요. (최소 500자, 최대 700자 입력가능)

사용자가 보는 화면 뒤에서 데이터를 안정적으로 처리하고, 기능이 끊김 없이 이어지도록 만드는 백엔드 개발자가 되고 싶습니다. 백엔드 분야에 관심을 갖게 된 계기는 주식정보 사이트 개선 프로젝트였습니다. 사용자 입장에서 필요한 정보를 더 쉽게 찾고 이해할 수 있도록 화면과 기능을 설계했는데, 프로젝트를 진행할수록 좋은 서비스는 화면만으로 완성되지 않고 그 뒤에서 데이터를 정리하고 필요한 정보를 정확하게 전달하는 구조가 함께 받쳐줘야 한다는 점이 더 중요하게 느껴졌습니다. 이후 빔웍스 인턴십에서 약 2개월 동안 백엔드 관련 업무를 직접 접하며, 서비스 뒤의 흐름과 구조를 다루는 역할이 잘 맞는다는 확신을 갖게 됐습니다.

강점은 결과만 맞추는 데 그치지 않고 구조와 원인을 끝까지 확인하는 점입니다. Verilog single cycle CPU 프로젝트는 Logisim으로 구현된 CPU를 Verilog로 옮겨 시뮬레이션한 과제였는데, 결과가 예상과 다르게 나오자 하위 모듈의 데이터 경로와 신호 전달 순서를 단계적으로 추적해 원인을 찾아 수정했습니다. 필요한 부분을 직접 파고들며 문제를 구조적으로 해결하는 성향은 정확성과 신뢰가 중요한 케이뱅크 백엔드 직무에 잘 맞는다고 생각합니다. 이런 강점을 바탕으로 많은 사용자가 반복적으로 이용하는 금융 서비스를 실제로 더 안정적으로 구현하고 개선하는 데 기여하겠습니다.

## 4. 은행의 상품이나 앱을 사용하면서 느꼈던 장점과 아쉬운 점을 구체적으로 설명해 주세요. 그렇게 느낀 이유를 작성하고, 내가 개발자라면 어떻게 개선·보완할지 제안해 주세요. ※ '이런 게 있으면 좋겠다'는 사용자의 니즈가 있을 때, 이를 어떻게 개발하고 실제 서비스에 적용할 것인지를 설명해주세요. (최대 1,000자 입력가능)

은행 앱을 사용하면서 가장 좋다고 느낀 점은 대부분의 업무를 직접 방문 없이 빠르게 처리할 수 있다는 점입니다. 계좌 조회, 이체, 인증, 각종 설정 변경까지 앱 안에서 해결할 수 있어 기본적인 편의성은 충분히 높다고 느꼈습니다. 반면 아쉬웠던 점은 원하는 기능이 있어도 찾는 과정이 직관적이지 않을 때가 있다는 점입니다. 예를 들어 계좌별 입출금 알림 설정을 바꾸려고 했을 때, 처음에는 계좌 관리나 알림 메뉴에서 찾을 것이라고 생각했지만 예상한 위치에 없어 여러 화면을 오가며 찾아야 했던 경험이 있었습니다. 기능이 없는 것은 아니었지만 사용자는 메뉴 구조를 외워서 들어가기보다 지금 무엇을 하고 싶은지부터 떠올리기 때문에, 원하는 기능이 생각한 위치에 없으면 앱 전체가 어렵게 느껴질 수 있다고 생각합니다. 특히 은행 앱은 상품, 보안, 인증, 관리 기능이 기준별로 나뉘어 있어 사용자의 행동 흐름과 실제 메뉴 구조 사이에 차이가 생기기 쉽다고 느꼈습니다. 자주 쓰지 않는 기능일수록 위치를 다시 기억하기 어렵다는 점도 아쉬웠습니다.

개발자라면 이런 문제를 메뉴를 더 늘리는 방식보다, 사용자가 실제로 기능을 찾는 흐름 기준으로 다시 설계해보고 싶습니다. 먼저 자주 찾지만 진입 경로가 긴 기능을 로그와 사용자 문의 데이터를 통해 확인하고, 많이 헤매는 기능은 검색 결과 상단 노출, 관련 화면 내 바로가기, 최근 사용 기능 추천 형태로 연결하겠습니다. 예를 들어 계좌 관리 화면에 들어왔을 때 자주 함께 찾는 한도, 알림, 자동이체, 보안 설정 같은 기능을 바로 볼 수 있게 묶어두면 탐색 부담을 줄일 수 있습니다. 또한 사용자가 특정 화면에서 오래 머물거나 여러 메뉴를 반복해서 이동하는 패턴이 보이면 해당 구간을 우선적으로 점검하겠습니다. 이후에는 개편 전후의 클릭 수, 기능 도달 시간, 중도 이탈률, 관련 문의 감소 여부를 비교해 실제 개선 효과를 검증하고 반영하겠습니다. 사용자가 원하는 일을 빠르게 끝낼 수 있게 만드는 것이 좋은 금융 앱의 중요한 기준이라고 생각합니다.
