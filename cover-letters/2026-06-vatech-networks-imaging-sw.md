## 1. 지원 직무를 지원하기 위해 본인이 준비해 온 노력을 소개해 주세요. (1,000자 이내)

영상 인식 결과를 사용자 기능으로 연결하고, 제품의 목적에 맞는 기술을 선택하는 역량을 준비해 왔습니다.

시각장애인 코딩교육 앱 ‘허밍블럭스’에서는 여러 블록을 한 장의 사진에서 동시에 인식해 음악으로 실행하는 기능을 개발했습니다. 여러 객체를 한 번에 검출하면서도 속도를 확보할 수 있어 YOLO를 활용했습니다. 그러나 모델의 출력은 각 블록의 종류와 위치 정보뿐이라 앱에서 바로 사용할 수 없었습니다. 위치 좌표를 기준으로 블록의 순서와 배치를 분석한 뒤, 어떤 악기가 어떤 순서로 연주되는지, 시작 시 한 번만 실행할지 무한 반복할지, 블록의 기울기에 따라 실행이 어떻게 달라지는지 등의 음악 규칙으로 변환했습니다. 이를 통해 객체 검출 결과를 음악 재생 기능이 사용할 수 있는 데이터 구조로 가공했습니다.

모바일 환경에서의 모델 추론 방식도 비교했습니다. PyTorch 기반 YOLO 모델은 Chaquopy를 통해 안드로이드에서 Python으로 구동했지만, 추론 결과가 나오기까지 지연이 있었습니다. 이를 개선하고자 모델을 TFLite로 변환해 Java에서 직접 실행하는 방식을 시험했습니다. 속도는 나아졌지만 인식 정확도가 떨어졌습니다. 빠른 응답보다 블록을 정확히 인식해 의도한 음악을 실행하는 것이 더 중요하다고 판단해 기존 PyTorch 방식을 유지했습니다. 이 경험을 통해 제품 목적과 사용자 경험을 기준으로 속도와 정확도를 비교해 선택하는 과정이 중요하다는 점을 배웠습니다.

컴퓨터비전 수업에서는 이미지 형성과 노이즈, 컨볼루션과 필터링, 경계 검출, 분할과 군집화, 특징점 정합과 객체 인식까지 영상 처리 흐름을 학습했습니다. 실습에서는 임계값과 필터 크기, Canny 기준값을 바꾸며 노이즈 제거와 경계 보존 결과를 비교했고, Hough 변환과 RANSAC을 구현하며 선과 형태를 검출하는 원리를 확인했습니다. 앞으로 영상 획득과 처리, 사용자 기능까지 이어지는 흐름을 이해하고 바텍 네트웍스의 이미징 솔루션을 안정적으로 구현하는 전문가로 성장하겠습니다.

앞으로 영상 획득과 처리, 조회와 사용자 기능까지 이어지는 흐름을 깊이 이해하고, 바텍 네트웍스의 Console과 Viewer를 안정적으로 개발하며, 제품 환경에서 신뢰받는 전문가로 성장하겠습니다.

## 2. 지금까지 경험한 1) 가장 어려웠던 일을 하나 소개해주시고, 2) 어떤 점이 어려웠는지, 3) 어떻게 극복했는지 구체적으로 소개해 주세요. (1,000자 이내)

가장 어려웠던 일은 시각장애인이 실물 블록으로 코딩을 체험할 수 있는 앱 ‘허밍블럭스’를 프로토타입에서 판매 가능한 제품으로 완성한 경험입니다. 전국 장애·비장애 대학생 창업경진대회를 계기로 시작해 약 1년 7개월 동안 개발했고, 집중을 위해 휴학을 결정했습니다. 안드로이드 앱을 처음부터 끝까지 완성해 본 경험이 없었습니다.

어려웠던 점은 기능 하나를 구현하는 것이 아니라, 촬영과 인식, 음악 실행, 화면, 외부 리소스를 하나의 사용 흐름으로 묶고 출시 기준을 스스로 정하는 일이었습니다. 프로토타입이 한 번 동작하는 것과 반복해서 사용할 수 있는 제품 사이의 차이도 컸습니다. 후처리 로직을 만들며 시작 블록이나 반복 블록이 없거나 변수 초기화가 누락되는 등 22가지 예외 상황을 발견했고, 그대로 실행하면 사용자가 원인을 알기 어려웠습니다. 음원과 디자인 리소스도 파일명, 크기, 위치, 길이, BPM 정보가 일정하지 않아 그대로 적용하기 어려웠습니다.

이를 해결하기 위해 전체 기능을 단계별로 나누고, 각 단계의 입력과 결과를 확인하며 개발했습니다. 22가지 예외 조건을 후처리 과정에서 검사해 화면에 원인을 안내하도록 만들었습니다. 메인 화면에서 음악 선택 화면을 바로 열어 클릭 수를 줄였고, UI 비율을 고정한 뒤 기기 화면 크기에 맞춰 조정해 버튼이 작게 보이는 문제도 개선했습니다. 외부 리소스는 누락 파일을 확인해 다시 요청하고, 빈 음원은 보완했으며, 길이와 BPM을 정리했습니다. 디자인 파일도 필요한 크기와 위치로 가공하고 이름을 앱 구조에 맞게 통일했습니다. 기능 확인 후에는 촬영부터 음악 실행까지 전체 흐름을 반복 점검하며 오류와 불편을 줄였습니다.

그 결과 허밍블럭스를 Google Play에 출시하고, 블록 키트를 유료로 판매하면서 연동 앱을 무료로 제공하는 형태로 운영할 수 있었습니다. 이 경험을 통해 제품 완성은 기능 구현에서 끝나는 것이 아니라, 예외 처리와 사용성, 협업 결과물까지 끝까지 점검해야 가능하다는 점을 배웠습니다.

## 3. 관심 분야와, 어떤 점에 흥미와 재미를 느꼈는지 구체적으로 소개해 주세요. (1,000자 이내)

관심 분야는 센서와 소프트웨어를 연결해 현실의 사물이 반응하도록 만드는 시스템입니다. 화면 안에서 끝나는 기능보다 코드가 장치의 움직임이나 빛, 소리로 이어지는 순간에 가장 큰 재미를 느낍니다.

이 관심은 고등학생 때 Arduino로 센서와 액추에이터를 다루며 시작됐습니다. 처음에는 예제 회로를 따라 만드는 수준이었지만, 원하는 형태로 직접 구성하고 싶어 PCB 설계를 독학했습니다. 이후 교육용 메이커 키트 ‘Paperware’를 만들 때 그 경험을 활용했습니다. micro:bit를 카드보드와 구리박 테이프로 만든 회로에 연결하는 구조였는데, 기존 네오픽셀 모듈은 납땜이 필요해 사용하기 어려웠습니다. 카드보드에 바로 끼울 수 있도록 접점을 넓힌 커스텀 모듈을 설계하고 시제품을 주문했습니다. 직접 설계한 회로를 카드보드 무드등에 적용했습니다.

webOS 스마트 화분 프로젝트에서는 관심의 범위를 시스템 전체로 넓혔습니다. Arduino에서 읽은 센서값을 Raspberry Pi의 webOS 서비스와 React 화면으로 전달하고, 화면의 제어 명령을 다시 장치로 보내 액추에이터를 동작시켰습니다. 개발 중 센서 이름과 단위, 전송 주기가 팀원마다 달라 값이 잘못 표시되거나 제어 조건이 어긋나는 문제가 있었습니다. 항목별 기준을 표로 정리하고 데이터 형식을 맞추자 센서값과 화면, 장치 동작이 하나의 흐름으로 연결됐습니다.

서로 다른 장치와 프로그램 사이에서 값이 어디서 끊기는지 찾고, 연결 기준을 맞춰 의도한 동작을 완성하는 과정이 즐겁습니다. 이 관심을 바탕으로 영상 장비와 소프트웨어 사이의 데이터 흐름을 안정적으로 연결하고, 사용자가 영상을 편리하게 활용할 수 있는 이미징 솔루션을 만들고 싶습니다.
