# 2019 네모감성 Link Cube · 스마트 타이머 무드등 — 자료/코드 재구성

> 상태: 2026-10-24 Google Drive 1차 검증. **당시 제출 문서에 적힌 목표**, **복원한 코드에 실제로 존재하는 기능**, **사용자의 개인 구현 기여**, **수상 기록의 증거 수준**을 분리한다. **2026-10-24 사용자 직접 확인:** 2019년 WCRC 스마트 타이머 무드등의 MakeCode 코드(타이머·기울기 감지·NeoPixel 제어·무선 통신)는 **전부 본인이 직접 작성**했다. **2026-10-25~26 추가 확인:** 2020년 교육 예제 **코드**는 본인이 전부 작성했고 영상 1개도 직접 제작했다. **본인은 교육을 진행하지 않았으며, 코드와 영상 1개 외의 교육자료는 제작하지 않았다.** 2019년 1월의 **'무드등 코딩영상' 1차/2차 편집 프로젝트·렌더링 파일 묶음**을 확인했고 영상 1개 제작 진술과 부합한다. **사용자 기억에 따르면 `무드등 코딩영상 2차편집.MP4`가 최종본 유력 후보**이나 외부 공개·배포 여부는 미확정이다. Link Cube 자동화 v1/v2와 조별 3개 파일의 저자 역시 미확정.

### 2026-10-29 출품 경위 추가 확인 — WCRC는 Paperware 기존 활동의 연장

본인 직접 회고에 따르면 **2019 WCRC 출품은 당시 진행 중이던 Paperware 프로젝트를 마침 열린 micro:bit 창작 대회에 가져간 것**이다. 따라서 이 문서에서 2019 WCRC 스마트 타이머 무드등의 코드를 **기술 구현 사례로 개별 분석하더라도 독립적인 신규 프로젝트 1개를 더 수행한 것으로 계산하지 않는다.** 2018 Paperware, 2019 Link Cube 제안 및 2021년경 PCB 개선의 정확한 제품/사업 구분은 별도 확인 영역이며, 2019 WCRC 당시 출품의 프로젝트 귀속에 대한 이번 직접 기억과는 구별한다.

**수상 해석:** 2019.11 2차본선 1위(금상) 공적조서 및 다른 대회의 팀 발표상 수상 기록은 수상 사실의 근거다. 다만 본인은 **경쟁 상대가 많지 않았던 대회여서 상을 받을 수 있었다고 기억**한다. 실제 참가 작품 수·경쟁률·심사 기준은 검증하지 못했으므로 **수상 실적을 치열한 경쟁 속 기술력 우위의 증거로 과장하지 않는다.** 이력서의 주력 가치는 당시 **본인이 작성한 MakeCode SW 및 코드에서 확인되는 문제 해결**에 둔다.

## 핵심 결론

2019년 네모감성 활동에는 적어도 **(A) 모듈형 micro:bit 교육 키트 Link Cube 구상(1월)**, **(B) 사회적 문제 해결 제품 시리즈로서 Link Cube 기획(7~8월)**, **(C) 진행 중이던 Paperware를 WCRC micro:bit 창작 종목에 출품한 스마트 타이머 무드등 프로토타입(10~11월)**이라는 성격이 다른 기록이 있다. 이름이 비슷하고 팀이 겹치지만 세 기획의 제안 기능 전체를 하나의 완제품으로 합산하지 않는다. 2019년 말~2020년 초에는 관련 자동화/교육용 MakeCode HEX가 더 남아 있다.

## WCRC 스마트 타이머 무드등 — 당시 제출 문서에서 확인한 문제 해결

**목표(기획서):** 어두운 환경에서 휴대전화 이용 시간을 사용자가 직관적으로 확인할 수 있도록 LED 색상 단계를 시간에 따라 바꾸고, 무드등의 회전 방향으로 타이머 시작 구간을 선택. 제품은 완제품 일방 공급보다 분해/조립 가능한 교육용 DIY 구성.

**하드웨어 제안/프로토타입:** 카드보드·쿠킹호일·기름종이를 이용하는 접이식 버전과 3D프린트 조각으로 조립하는 큐브형 버전을 **제출 문서에서 두 프로토타입으로 기술**하고 제작 모습을 첨부. 두 유형의 생산량, 내구성, 개별 제작 담당자는 미확인.

**오류 1 — 회전 이후 LED 색상 미갱신:** 제출 문서는 처음의 제어 구조에서는 조명 작동 중 회전해도 색이 갱신되지 않았다고 설명. 무한반복 루프를 재구성해 기울기 센서 값을 반복 확인하며 새 상태로 재실행하는 방식을 채택했다고 기록. 복원 코드 `moodlight-main-5min`/`10sec`의 `getstate()` 및 루프 내 상태 재확인 경로와 부합.

**오류 2 — BLE와 NeoPixel 확장 기능의 동시 사용 문제:** 제출 당시 두 라이브러리를 함께 사용하기 어려웠다고 서술. 대안 3개를 비교한 후, **Bluetooth 대신 micro:bit 간 radio 통신을 이용해 별도 컨트롤러의 A/B 버튼으로 사용 시작·종료 신호를 보내는 방식 적용**이라고 적었다. 따라서 **휴대전화 디스플레이 ON/OFF를 자동 감지하는 완성 기능**은 확인되지 않는다. BLE 동작 제약은 당시 환경/라이브러리에 대한 팀의 보고로 기술하고, 모든 micro:bit 환경의 일반적 불가능성으로 확대하지 않는다.

## 실제 HEX에 내장된 MakeCode 소스 분석

Google Drive에 보관된 Intel HEX의 내장 소스 메타데이터/압축 소스(`main.blocks`, `main.ts`, `pxt.json`)를 복원하여 읽었다. 소스는 **기능이 코드에 존재한다는 자료 근거**이며, 작성자 범위는 **사용자 직접 확인**에 따른다. 실제 현장 시연과 모든 버전의 연동 성공은 아직 미확인이다.

### 2019.10 스마트 타이머 무드등 — **본인 소프트웨어 전체 작성 확인**

2019 WCRC 출품작의 MakeCode 소프트웨어를 본인이 전부 작성했다는 사용자 확인(2026-10-24)을 기록한다. 직접 기여 기능은 타이머의 단계/시간 경과 관리, 가속도 센서를 통한 회전·기울기 상태 입력, NeoPixel RGB 제어, 조도 조건, 별도 micro:bit의 버튼과 radio 신호 교환이다. 아래 파일들은 해당 프로젝트 개발/시험 과정의 당시 산출물이다. 다만 각 바이너리를 그대로 조합했을 때의 통합 동작 성공은 별도 확인이 필요하다.

- `microbit-moodlight-191003.hex`: 4방향 기울기를 X/Y 가속도 **±512 임계값**으로 상태 구분, NeoPixel 색상 변경 루프. 초기 구현과 추후 버전의 차이가 보임.
- `microbit-moodlight-main-rainbow.hex`: 12채널 NeoPixel(P2)에 시간에 따른 RGB 색상 패턴.
- `microbit-moodlight-main-5min.hex` / `10sec.hex`: 상태별 시간 제어를 서로 다른 단위 시간(`utime=30000`, `1000`)으로 구성해 시험하는 버전. 기울기 상태 재확인, 조도 기준 40, 라디오 수신 기반 `sign` 상태, NeoPixel 12개 색상 변화 제어 경로가 존재. 파일명만으로 실제 정밀 타이밍 성능을 입증하지 않음.
- `microbit-moodlight-main-5sec.hex` 및 `-nbr.hex`: 조도 조건 포함/제거 변형을 확인. 짧은 시험 주기의 추가 반복 산출물로 볼 수 있음.
- `microbit-moodlight_controller.hex`: 무선 그룹 42에서 버튼 A/B를 이용해 `square_sensitivity`라는 이름으로 0/1 값 전송.
- **정적 통합 확인 필요:** 현재 확인한 메인 변형은 `radio.onReceivedNumber`를, 컨트롤러는 `radio.sendValue(...)`를 사용한다. 따라서 이 **특정 두 파일을 그대로 페어링했을 때** 수신이 정상적이라고 검증할 수 없다. 다른 변형·현장 동작 여부 미확인.

### 2019.12~2020.01 Link Cube 자동화와 교육 예제

- `linkcube-automata-v1.hex`: A 버튼은 **조도 감지 모드**(조도 40 미만), B는 **흔들기 모드**를 선택하며 P2 analog 출력값을 0/1023으로 토글.
- `linkcube-automata-v2.hex`: A/B 조건을 각기 on/off 토글로 관리. **조도 임계값 80** 또는 흔들기 조건에 따라 P2 아날로그 출력 0/1023을 제어. v1의 배타적 모드에서 독립 플래그 방식으로 구조가 변화.
- `교육자료/examples/microbit-ex10-neopixel.hex`: 버튼으로 7색 배열을 순회하고 NeoPixel 8채널을 구동. `교육자료/`의 다른 예제 파일명은 LED, 버튼, 조도, 자기장, 가속도, 서보 등 입문/심화 학습 범위를 보여 줌.
- **2026-10-25~26 사용자 확인:** `교육자료/examples/`와 기초·심화반, 교육용 무드등의 **예제 코드는 본인이 직접 작성**했다. **2019년 1월 무드등 코딩영상도 1개 직접 제작**했으며, `무드등 코딩영상.MP4`와 `무드등 코딩영상 2차편집.MP4`, Vegas 편집 프로젝트, 코딩 대본이 자료로 남아 있다. **2차 편집 MP4가 최종본일 것으로 사용자 기억에 남아 있으나** 영상 배포 여부와 편집 세부 담당은 미확정이다. **교육 진행은 하지 않았고, 코드와 영상 1개 외 교안·기타 교육자료는 제작하지 않았다.** [별도 분석](linkcube-education-2020.md) 참고. `linkcube-automata-v1/v2.hex`와 조별 `microbit-1조/2조/3조.hex`의 저자·용도는 미확정.

## 이력서 재구성 (SW 직접 구현 확인, 현장 동작 범위 별도 검증)

**상황:** 저렴하고 조립 가능한 micro:bit 메이커 교육 키트를 기반으로, 시간 변화와 자세 입력을 이용하는 스마트 무드등을 WCRC 창작 종목에 출품.

**문제:** 작동 중 회전 시 LED 갱신이 안 되는 제어 흐름; 당시 BLE/NeoPixel 확장 기능 동시 사용의 충돌.

**판단:** 루프 내 기울기 상태 재평가 및 BLE 대신 micro:bit 자체 radio 기반 원격 입력 채택.

**조치:** 개인이 MakeCode로 시간·상태에 따른 LED 색상 제어, 회전·기울기·조도 센서 입력 처리, micro:bit radio 컨트롤러 및 메인 제어 프로그램을 작성했다. 제어 중 회전시 색상이 갱신되지 않던 오류를 반복 상태 확인으로 고치고, BLE/NeoPixel 확장기능 충돌을 radio 사용으로 우회했다. 카드보드/3D프린팅 두 물리적 프로토타입은 팀 출품 자료에 기록됐으나 각 기체의 개인 제작 담당은 미확정이다.

**결과:** WCRC 스마트 무드등의 **소프트웨어 전체 직접 작성은 사용자 확인 완료**. 2019.11 WCRC 2차 본선 참가 및 **1위(금상) 공적조서 기록**은 당시 자료에서 확인. 무선 명령 송수신의 특정 버전 페어링, 타이머 최종 실기 검증, 실물 설계 담당, 실제 상장 원본은 확인 보류.

> **경험기술서 잠정 문장 — 개인 SW 직접 구현 확인:** “2019년 WCRC micro:bit 창작 부문에 출품한 스마트 타이머 무드등의 **MakeCode 소프트웨어 전체를 직접 구현**했습니다. 기울기에 따른 타이머 상태 변환과 NeoPixel RGB 조명 제어를 구현하고, 회전 중 색상이 갱신되지 않는 문제를 반복 상태 확인 방식으로 수정했습니다. 당시 BLE와 NeoPixel 확장기능 충돌 문제는 micro:bit radio 기반 원격 입력으로 우회했으며, 팀은 WCRC 2차 본선에서 **1위(금상)**를 기록했습니다.” 휴대전화 연동 자동 ON/OFF나 모든 코드 버전의 무선 통신 정상 동작을 단정하지 않는다.

## 직접 확인이 필요한 사항

1. **개인 저작 확인 완료:** 2019년 WCRC 스마트 무드등의 타이머·기울기·NeoPixel·radio를 포함한 MakeCode 소프트웨어 전체를 본인이 직접 작성(사용자 확인). 별도의 후속 Link Cube 자동화 및 2020 교육 예제의 저작 범위는 여전히 확인 대상.
2. **실제 현장 시연:** 2019 WCRC에서 조도/기울기/NeoPixel/무선 ON/OFF가 어디까지 실제 작동했는가? 일부 시험용 HEX에서 송수신 이벤트 형식이 다르게 보이는 이유는?
3. **WCRC 성과 증빙:** 2019년 11월의 1위 공적조서 외에 최종 상장/시상 기록이나 이전 WCRC 1차 수상 기록이 있는가?
4. **연결 관계:** **WCRC는 진행하던 Paperware의 대회 출품이었다는 점은 사용자 확인 완료**. 2019년 1월 모듈형 Link Cube, 7~8월 소셜벤처 Link Cube와 WCRC용 스마트 타이머 무드등이 실제 동일 설계/제품의 어떤 버전 관계였는지는 추가 확인 가능 항목.
5. **교육 자료 역할 확인 완료:** 2020 예제 코드와 영상 1개만 제작, **교육 진행 및 기타 교안/자료 제작에는 참여하지 않음**. 무드등 코딩영상의 1차·2차 편집 파일은 찾았고, **2차 편집본을 최종본 유력 후보로 기록**하고, 추가 확인이 필요하다면 **외부 공개·배포 여부/편집 세부 범위** 및 Link Cube 자동화 v1/v2의 저작 여부에 한정. 조별 파일은 기억이 없어 미확정 유지.
