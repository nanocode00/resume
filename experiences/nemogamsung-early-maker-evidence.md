## 기술적으로 확인한 소스

### 2018 micro:bit MicroPython — `controller.py` (**본인 직접 작성, 사용자 확인**)

- A/B 버튼 조합을 `U`(up), `D`(down), `S`(stop) 라디오 메시지로 전송.
- 버튼을 누르지 않을 때 가속도 센서 X/Y값을 읽고 절댓값 70 이하는 0으로 간주하여 미세 움직임을 제거.
- 두 축 값의 자릿수 길이를 붙인 문자열로 전송하고, 5×5 LED matrix에 상하좌우/대각 방향 표시.
- `radio_test.py`는 명령 수신 후 LED 방향 표시를 수행함. 이 파일은 발신 `controller.py`의 동작을 수신측에서 확인하려는 테스트 구현으로 해석 가능하지만, **이 파일의 개인 작성 여부와 실제 통신 성공은 확인되지 않음**.
- **검증 경계:** 직접 구현이 확인된 것은 컨트롤러 송신·입력 처리 부분이다. 드론 자체의 제어기 구현이나 비행 완료까지 증명하지 않음.

### 2018 드론 기체 제작·조종 시도 — 사용자 직접 확인 (2026-10-24)

- **상황:** 카드보드와 부품을 이용해 실제 드론 기체를 만들고, 직접 만든 micro:bit 컨트롤러로 조종을 시도했다.
- **문제:** 사용자의 당시 관찰/판단에 따르면 카드보드 프레임과 부품의 무게에 비해 모터의 추진력이 부족했다. 무게·추력·전류의 실측 데이터는 확보하지 못했다.
- **판단/조치:** 직접 구현한 버튼/기울기 기반 무선 컨트롤러를 활용해 제작 기체의 조종을 시도했다. 기체의 구체적인 설계 변경·모터 교체 등 추가 대응은 확인되지 않았으므로 기재하지 않는다.
- **결과:** **이륙 실패.** 기체를 실제로 제작해 시도한 경험은 확인됐으나 무선 명령이 수신되어 모터에 반영됐는지, 지상 동작 확인의 세부 범위는 아직 알 수 없다.
- **배운 점으로 활용할 해석(후속 면접용, 사실/추론 구분):** 임베디드 SW 구현만으로 완성되지 않는 물리 시스템의 제약(하중·추력 등)을 보여 주는 사례. 다만 당시 본인의 구체적 판단·회고를 별도로 확인하기 전에는 특정 교훈을 당시에 의식했다고 단정하지 않는다.

**경험기술서 잠정 문장:** “micro:bit의 버튼·가속도 입력을 무선 명령으로 변환하는 MicroPython 컨트롤러를 직접 구현하고, 카드보드 기반 드론 기체를 제작해 조종을 시도했습니다. 기체·부품 무게에 비해 모터 추진력이 부족해 이륙에는 실패했으며, 기체 제어용 Arduino 코드는 드론 관련 서적의 제공 예제를 활용했습니다.”

### 2018 Arduino — `drone.ino` (**드론 관련 도서 제공 예제, 개인 저작물 아님**)

**출처/기여 구분:** 사용자가 드론 관련 도서의 제공 자료라고 명확히 확인했다. 아래는 코드에 포함된 **참고 기술 구성**일 뿐, PID 제어기·IMU 필터·Arduino 비행제어 소프트웨어를 직접 구현한 이력으로 사용할 수 없다. 도서명·예제 라이선스는 별도 확인 필요.

- `MPU6050`(I2C 주소 `0x68`) 가속도/자이로 14바이트 읽기, 초기 센서 보정 및 기울기 추정.
- 자이로 적분값과 가속도 추정값을 `ALPHA=0.96`으로 결합하는 complementary filter 구현.
- roll/pitch/yaw 목표값·변화율을 입력으로 하는 `dualPID` 함수와 모터 4개 PWM 범위 0~255 제한 구현.
- `Serial1`로 들어온 MSP 형식 명령을 파싱해 throttle 및 기울기 목표값을 조정하는 경로가 있음.
- 사용자가 직접 기체를 만들고 조종을 시도했으나 **이륙에 실패했다**고 확인했다. 따라서 비행·안정화 성능을 달성한 구현으로 서술하지 않는다. 또한 예제 소스에 포함된 제어 알고리즘을 본인의 작성 성과로 귀속하지 않는다.

### 2019 무드박스 및 2020 교육 코드

- `추가 자료설명.pptx`는 NeoPixel RGB/밝기 범위, 버튼 A/B에 따른 분기, 기울기 X/Y/Z축 기반 색상 변화와 소등 조건을 설명.
- `microbit/moodlight-final/`, `moodlight-5sec/`에는 여러 main/controller HEX 변형이 남음.
- **추가 코드 복원(2026-10-24):** MakeCode HEX의 LZMA 임베디드 payload에서 `main.ts`/`main.blocks`를 복원했고, 기울기 ±512 기반 4방향 상태 제어, 조도 40 기준, NeoPixel 12채널 RGB 타이머, radio group 42 및 시험 주기별 버전을 확인. `moodlight_controller`는 `radio.sendValue`, 일부 메인은 `onReceivedNumber`이므로 정확히 해당 조합의 통신 성공까지 확정 불가.
- `2019 국제로봇콘테스트_네모감성팀.hwp` 원문에서 **회전 시 색상 갱신 오류 수정**과 **BLE/NeoPixel 확장 라이브러리 충돌 → micro:bit 간 radio로 대체**했다는 당시 기술적 판단이 명시돼 있다. 카드보드형 및 3D프린팅형 **두 프로토타입**도 문서에 기재됨. [2019 Link Cube·스마트 무드등 조사 원장](linkcube-2019.md) 참고.
- 2020 `교육자료/examples/`에는 LED 출력, 버튼·조건문, 조도, 자기장, 가속도, servo, NeoPixel 및 기초·심화반 자료가 정리되어 있음. **예제 코드는 본인이 모두 직접 작성했다고 2026-10-25 확인**. 단, `microbit-1조/2조/3조.hex`의 작성자·용도는 오래되어 기억나지 않는다고 밝혔으므로 **학생 작품이라고도, 본인 저작이라고도 귀속하지 않음**. [교육자료 별도 분석](linkcube-education-2020.md) 참고.
- **개인 저작 확인(2026-10-24):** 2019 WCRC 스마트 무드등의 MakeCode 타이머·기울기 감지·조도·NeoPixel RGB·micro:bit radio 기능은 사용자가 **전부 직접 작성**한 것으로 확인했다. HEX 내장 소스와 당시 제출 문서로 구현 내용을 교차검증했다. 다만 실제 현장 통신 및 개별 테스트 버전의 정상 작동은 별도 검증 사항이다.
- **2026-10-25~26 추가 확인:** 2020 교육 예제 코드는 본인이 직접 작성했고 영상도 1개 제작했다. **본인은 교육 진행을 하지 않았으며 예제 코드·해당 영상 1개 외의 교육자료도 제작하지 않았다.** **2019년 1월 `무드등 코딩영상` 1·2차 편집 프로젝트 및 MP4, 화면 녹화, 대본 파일을 발견해 제작 영상의 주제/자료 묶음을 좁혔다.** **사용자 기억상 `무드등 코딩영상 2차편집.MP4`가 최종본으로 추정되며**, 실제 외부 공개·배포 여부와 대본·교안 작성자는 미확정이다. Link Cube automata v1/v2 및 조별 산출물 저자도 미확정이다. 코드 존재/개인 저작 확인을 강의·수업 운영 실적으로 확대하지 않는다.

## 이력서 선별 시 권장 구조

1. **Paperware PCB 개선:** 2022년 당시 발표와 이후 회고, 2026-10-26 사용자 직접 확인을 대조. **2021년경 EasyEDA NeoPixel PCB 직접 설계, LCSC 가격 비교·부품 선정, JLCPCB 발주 및 실제 활용**을 확인한 경험. [Paperware 상세 원장](paperware.md) 참고. 초기 `test`와 **첫 발주 `neopixel`의 EasyEDA 회로도·PCB·BOM 화면을 확인**. `neopixel`은 WS2812C 9개를 3×3 배열한 보드이며, **JLCPCB PCB 제조 발주 후 별도 부품을 직접 납땜**했다고 사용자가 확인했다. **후속 `nemopixel`은 WS2812E 8개, 클립 홈, 로고, 자동조립을 적용했고 납 잔류 문제를 관찰한 것으로 확인**. **`nemopixel_rev2`는 XL-5050RGBC-WS2812B 8개로 부품 교체·외형 수정 후 크림납/스텐실/열풍 실장을 시도했지만 실제로는 인두 수동 납땜으로 마무리했다고 확인**. 최종 적용판/주문 증빙/점등 실측은 아직 미확인.
2. **micro:bit 무선 컨트롤러·드론 제작 시도:** `controller.py` 직접 구현에 따라 **버튼/가속도 입력 처리 → 라디오 명령 패킷 전송 → LED 상태 표시**를 개인 SW 사례로 분리할 수 있음. 제작 기체의 **추력 부족에 따른 이륙 실패**를 결과로 명시하며, **책의 `drone.ino` 내부 알고리즘은 기여 실적에서 제외.**
3. **2019 WCRC 스마트 타이머 무드등:** **전체 SW 직접 구현**(타이머/기울기/NeoPixel/radio)이 확정된 독립적인 임베디드 SW 경험. 기울기 갱신 문제 수정, 라이브러리 충돌 우회, 당시 수상 기록과 연결하되 최종 통신 동작은 미확정으로 보존.
4. **2020 micro:bit 교육용 코드 개발:** 기초 LED/버튼부터 센서·서보·NeoPixel 응용까지 **예제 프로그램을 직접 작성**하고, **2019년 1월 무드등 코딩 튜토리얼 영상 1개를 제작**(`무드등 코딩영상.MP4` 및 `무드등 코딩영상 2차편집.MP4`와 관련 편집 원본 발견; 2차 편집 MP4가 최종본 유력 후보(사용자 기억), 공개 여부 미확정). **강의/교육 운영은 하지 않았고 PPT·기타 교육자료 제작에도 참여하지 않았으므로** 이력서에는 코드 개발과 확인된 영상 작업만 기재한다.
5. **Link Cube automata 및 조별 구현예시:** 기술 산출물은 확인했으나 개인 저작 미확정으로 구분.

## 검증 질문 (자료 확인 이후에만 사용자 기억을 요청)

- **작성자·기체 제작·이륙 결과 확인 완료:** `controller.py`는 사용자 직접 구현, `drone.ino`는 드론 관련 도서의 제공 예제. 카드보드 기체를 제작·조종 시도했으나 모터가 하중을 감당하지 못해 이륙 실패. 추가 확인은 **무선 수신/모터 반응의 실제 검증 범위와 프레임·부품·모터 제원**에 한정.
- **2019 WCRC 무드등 SW 전부 본인 작성 확인 완료.** **2020 micro:bit 교육 예제 코드도 전부 본인 작성 확인 완료(2026-10-25).** 남은 질문: 대회 시연 당시 어떤 버전 조합으로 통신했는지, Link Cube automata v1/v2는 누가 작성했는지. **조별 1·2·3조 파일은 사용자도 기억나지 않으므로 미확정 유지**.
- **2026-10-26 PCB 연관성 확인:** 2021년경 NeoPixel PCB 설계·발주·사용은 Paperware 관련 작업으로 사용자 재확인. 다만 2018년 Paperware 원형 활동의 조직적 연속성이나 정확한 제작 월은 미확정.
- 2020 기초·심화·무드등 교육 예제 코드 직접 작성과 **교육 진행 없음**, 기타 교육자료 미제작을 확인. 본인이 제작한 **무드등 코딩영상 편집/출력 파일 묶음은 발견**했으며, **2차 편집 MP4가 최종본일 것으로 기억**하나 실제 외부 공개·배포 여부는 미확정. 교육 회차·교육 효과를 본인의 실적으로 기재하지 않는다.
- 2019 WCRC 수상작의 실제 작동 범위 및 개인 기술 역할은 무엇인가?

**2026-10-26 EasyEDA 신규 스크린샷 증거:** 사용자 계정의 `test`/`PCB_test` 회로도, PCB 레이아웃, LCSC 부품번호가 채워진 BOM을 확인했다. `test`는 사용자가 가능성 검증을 위해 **제일 먼저 만든 보드**로 특정했다. BOM에는 `C41851` 100nF 커패시터(3개, 화면 단가 `0.007`), `C2843785` XL-5050RGB 계열 LED(3개, 화면 단가 `0.056`), 3핀 연결부가 보인다. PCB의 넓은 접점 패드는 카드보드 연결 목적과 부합하지만 실제 성능 검증은 별개다. 후속으로 `neopixel`, **실제 확인된 프로젝트명 `nemopixel`**이 있다. 이전 기록의 `neopixel_rev2`는 추정명으로 잘못 기재한 것이며, **실제 프로젝트는 앞선 `nemopixel`과 별도의 `nemopixel_rev2`**인 것으로 화면에서 확인했다. 둘을 합치지 않는다. **이 초기 보드가 최종 JLCPCB 발주·실사용된 설계라고 단정하지 않으며**, 화면 단가는 당시 지불액으로 사용하지 않는다. [Paperware 상세 증거 기록](paperware.md) 참고.

**2026-10-26 `neopixel` 첫 발주판 화면·제작 방식 확인:** 사용자 계정 스크린샷 3장에 `neopixel` 회로도와 `PCB_neopixel`, BOM이 남아 있다. **WS2812C(LED1~9) 9개(3×3)**, **0.1µF 커패시터(C1~C9) 9개**, `JP1` 3핀 점퍼, **DIN/VCC/GND 접점**이 보인다. BOM은 Worldsemi WS2812C의 LCSC 부품번호 `C114587`과 화면 표시 단가 `0.144`를 보여 주지만, 이는 **당시 실제 구매 단가나 결제 기록으로 볼 수 없다**. 이 프로젝트가 `test` 다음의 **첫 실제 JLCPCB 발주 보드**였고, **부품은 별도 구매하여 직접 납땜**했다는 사실은 사용자 직접 진술. **첫 발주 PCB의 PCBA 외주 조립 실적으로 쓰지 않는다**. JLCPCB 주문 영수증, 실제 LED 점등, 무드등 실사용판(이후 rev2 여부)은 추가 확인이 필요하다. [Paperware 상세 증거](paperware.md) 참고.

**2026-10-26 `nemopixel` 후속 제작판·문제 확인:** 사용자 제공 스크린샷에서 EasyEDA `nemopixel` 회로도 표제란 날짜 **2021-10-03**, WS2812E **8개** + 100nF 커패시터 **8개**, 3핀 접점 및 LCSC BOM을 확인했다. LED `C139127`, 커패시터 `C307331`로 부품 변경. `PCB_nemopixel`은 **3-2-3 배치**, 클립 결합용 상단 좌우 홈, 로고/디자인, 자동조립 목적의 홀 2개가 특징이다. `PCB_nemopixel_r`에는 **8 LED 원형 배치 대안**이 있지만 사용하지 않기로 했다고 사용자 확인. **PCBA 자동조립 서비스 실사용 후 뒷면 넓은 접점 패드에 굳은 납으로 표면 요철이 생기고 홀 부근에도 납이 남은 것**을 관찰했다는 사용자 진술을 기록하되, **홀 위치·마스크/페이스트·제조 공정 중 무엇이 원인인지는 분석 전**이다. 1차 `neopixel`의 직접 납땜과 구별. [Paperware 세부 기술/근거](paperware.md).

**2026-10-26 `nemopixel_rev2` 추가 설계/조립 기록:** 사용자 제공 EasyEDA 3개 화면에서 `nemopixel_rev2` 회로도 표제란의 **2021-12-28** 날짜(제조/발주일 아님), 주소 지정 RGB LED **XL-5050RGBC-WS2812B ×8**, 100nF 커패시터 ×8, `HEADER3` 연결부, **3-2-3 배열/중앙 로고/하단 둥근 모서리** 형태를 확인. BOM은 LED LCSC `C2843785`(화면 표시 단가 `0.056`) 및 커패시터 LCSC `C1525`(`0.004`)를 표기. **실제 결제 단가와는 구별한다.** 사용자 기억상 `nemopixel`에 이어 부품을 한 번 더 바꾸고 하단 코너를 다듬었으며, **크림납·금속판(스텐실로 추정)·열풍 방식의 납땜을 시도했으나 판 크기가 맞지 않아 인두로 직접 납땜**했다. 실제 리플로 공정 성공이나 이전 자동조립의 납 잔류 문제 수정 성공은 주장하지 않는다. 이전 `nemopixel`에도 하단 곡면이 보이므로 **둥글림의 정량적인 차이는 CAD 대조 전까지 미확정**. [Paperware 상세 기록](paperware.md).

**2021년경 PCB 작업에 대한 추가 근거:** 2022.04 진로활동 발표 `초안.pptx`는 “작년, 복학하기 전에” Paperware용 PCB 모듈 개발과 납땜 진입장벽 완화 목적을 당시의 표현으로 설명한다. `PCB/`로 보관된 Drive 폴더는 파일 수정 기록이 대부분 2018년인 OrCAD 설치·부품/데이터시트 참고자료이며, 이번 조사에서 **2021년 NeoPixel 모듈의 특정 CAD/Gerber/발주 원본이라고 식별하지 못했다**. 2026-10-26 사용자가 NeoPixel 모듈 PCB 직접 설계·주문·사용을 재확인했으며, **EasyEDA 설계·LCSC 부품 가격 비교 및 선정·JLCPCB 발주** 경로도 추가로 확인했다. 단, 업체 계정에 해당 프로젝트·견적·주문 데이터가 남아 있는지는 아직 확인하지 못했다.
