### `neoboard` — ATtiny85 + NeoPixel 통합 PCB 및 제작 후 수리 경험 (2026-10-26 추가 발굴)

**프로젝트 귀속·시기:** EasyEDA 개인 프로젝트 `neoboard`의 `Sheet_1`, `Sheet_2`, `PCB_neoboard`, BOM 스크린샷 4장을 사용자가 제공했다. **실물 PCB가 제작되어 수령/수리/일부 동작까지 시도했다는 사실은 사용자 직접 진술**. 기존 Paperware NeoPixel 전용 PCB와의 **조직적/제품적 관계 및 제작 연월은 아직 확인하지 않았다.** 별도 확장 설계로 기록하고 기존 NeoPixel 버전의 또 다른 Rev 또는 제품 출시 실적으로 합산하지 않는다.

**회로·PCB 확인(A: 사용자 업로드 EasyEDA 화면)**

- `Sheet_2`: **WS2812E 주소 지정 RGB LED 8개**, 각 LED 근처 100nF 커패시터가 직렬 데이터 체인 및 VCC/GND로 구성된 NeoPixel 회로.
- `Sheet_1`: **ATtiny85-20SU(U2)** 기호, Micro-USB 커넥터 `USB1`, 제너 다이오드 `D1/D2`, 별도 다이오드 `D3`, 저항/커패시터, **2×3 6핀 `H1`** 등이 보인다. 사용자는 이 6핀을 **펌웨어 기록을 위한 헤더**로 추가했다고 확인했다. 회로상 AVR ISP/ICSP로 추정되지만 **실제 프로그래밍 성공/케이블 핀맵은 소스·시험 기록 미확인**이다.
- `PCB_neoboard`: 8개 LED가 외곽을 둘러싼 다각형 PCB, 중앙 MCU/수동소자, 하단 Micro-USB 및 2×3 핀헤더 풋프린트. 제조 및 기구 설계 형태를 보여 주나 사진만으로 모든 배선이 올바르게 작동한다고 주장하지 않는다.
- **BOM 주목:** 회로도 기호는 **`ATTINY85-20SU`**이지만, BOM의 MCU 항목은 **`ATTINY45-20SUR`**로 보인다. **회로상 의도 MCU와 부품 BOM 간 불일치**가 화면에서 확인되어, 사용자의 'ATtiny45를 잘못 주문해 ATtiny85를 다시 구매'했다는 회고와 일치한다. 언제 BOM이 수정됐는지, 이 BOM이 실제 최초 주문과 정확히 같은지는 별도 확인해야 한다.
- BOM은 8개 WS2812E(`C139127` 6+2행), 100nF 커패시터 `C1525` 9개(USB/MCU 측 포함), 4.7µF `C23733` 1개, `BZT52C3V6S` 2개(`C353525`), `1SS367,H3F` 1개(`C150185`), Micro-USB `C381144` 및 6핀 커넥터 `C706893` 등을 표시한다. **표시 가격을 당시 결제액이나 최종 조달 기록으로 사용하지 않는다.**

**저작·참고 경계(C: 사용자 진술)**

- ATtiny 부분은 **시중에 판매되는 기존 제품의 공개된 회로도를 참고·사용**했다고 사용자 확인. **ATtiny USB/제너 회로를 독창적으로 설계하거나 해당 참고 설계의 최초 저자라고 주장하지 않는다.** 반면 NeoPixel과의 통합 및 보드 설계·제작 과정, 펌웨어 업로드용 6핀 헤더 추가와 실제 문제 해결은 본인 활동으로 기록한다.
- **ATtiny 펌웨어는 ATtiny85용으로 준비되어 있었다고 기억**하나 펌웨어 소스·작성자·실제 프로그램 구조는 아직 미확인. **ATtiny 펌웨어를 직접 개발했다고 이력서에 쓰지 않는다.**

**제작 후 문제 발견·대응(C: 사용자 회고)**

| 문제/상황 | 조치 및 확인 가능한 결과 | 원인 단정 금지 |
|---|---|---|
| **초기 동작 실패** | 다이오드 **1개의 배치 방향이 반대**였음을 확인하고, 제작물에서 **수동으로 방향을 뒤집음** | 정확히 어느 D1/D2/D3인지 아직 미확정. 실제 장착 방향 오류와 설계 심볼 방향 오류의 책임 단계 구분 불가 |
| **MCU 선정 불일치** | 처음에는 **ATtiny45를 구매**, 준비한 펌웨어가 ATtiny85용임을 확인하고 **ATtiny85를 재구매** | 펌웨어 용량·메모리 제한 등 기술 원인은 소스 없이 추론하지 않음 |
| **NeoPixel 일부 미점등** | 제작된 여러 보드에서 **LED 일부가 점등되지 않는 현상**을 발견, 손상된 것으로 판단한 LED를 **교체하여 일부 보드 복구** | '과열로 LED가 사망'은 당시 추정. 열화 원인·불량률·복구 수량 미확인 |
| **Micro-USB 높이 간섭** | 하단의 Micro-USB 5핀 커넥터 높이로 인해 **PCB 한쪽이 들리는 현상 관찰** | 구조 개선을 적용했다는 기록은 없음 |
| **의도하지 않은 마킹** | 제조 발주 시 **시리얼 번호 표시 옵션을 끄지 않아 뒷면에 번호 인쇄** | 제조사·마킹 기능의 정확한 옵션명, 제거 여부 미확인 |

**평가 가능한 성과의 범위:** 설계·제조를 직접 경험한 뒤 **역방향 다이오드 재작업, MCU 재구매, LED 교체를 통해 일부 보드의 동작을 복구한 사실**은 확인. 모든 PCB가 정상 동작하거나 장기 안정성 시험을 통과했다는 근거는 없고, 잘못 설계된 회로를 모두 정상화했다고 주장하지 않는다. 강한 사례는 완전한 성공보다는 **하드웨어-부품-펌웨어-제조 결함을 서로 다른 원인으로 분리하고 대응한 과정**이다.

**이력서용 잠정 문장(실제 직무 적합성에 따라):** “공개된 ATtiny 기반 회로를 참고해 WS2812E NeoPixel 8개를 통합한 PCB를 설계·제작했습니다. 제작 후 부품 방향 및 MCU 선정 오류, LED 미점등, USB 커넥터 높이 간섭과 제조 마킹 문제를 발견하고, 다이오드 재작업과 MCU·LED 교체를 통해 일부 보드의 동작을 복구했습니다.” 단, **상용 ATtiny 회로 및 미확인 펌웨어 자체를 직접 개발했다고 표현하지 않는다.**

### `nemotiny` — ATtiny85 기반 micro:bit 대체 제어보드 설계·제작 (2026-10-26 추가 발굴)

**역할·귀속 경계:** 사용자는 **micro:bit를 대체할 목적**으로 `nemotiny`를 만들었고, 기존 ATtiny 보드 회로를 기반으로 **배터리 입력과 후면 센서 연결 패드** 등을 추가했다고 직접 설명했다. 이는 **NeoPixel LED를 탑재한 `neoboard`와 구분되는 제어 보드**다. 특히 `neoboard`의 **독립 2×3 ICSP/ISP 헤더와 달리 `nemotiny`에는 별도의 ICSP 헤더를 만들지 않고 프로그램 업로드에 필요한 신호 접점을 PCB 뒷면 패드로 분산 배치**했다고 2026-10-26 추가 확인했다. 관련 Paperware/Link Cube 계열 활용 목적은 맥락상 유력하나, **실제로 어떤 완성 제품에 적용됐는지는 확인되지 않았다.** ATtiny 기반 참고 회로의 원천 저작이나 펌웨어를 본인이 처음부터 개발했다고 기재하지 않는다.

**화면에서 직접 확인한 기술 산출물(A):** 사용자가 EasyEDA의 `nemotiny/Sheet_1`, `PCB_nemotiny`, `PCB_nemotiny_a`, BOM 화면 **5장**과, **`PCB_nemotiny` 추가 PCB 레이아웃 화면 1장**을 제공했다. 회로도 표제란에 **2022-01-13**이 보이지만 *설계 문서상 날짜*이지 제조/발주일은 아니다.

- **제어부:** `ATTINY85-20SU`(`U1`), 택트 스위치(`SW1`), 저항, 표시용 LED(`LED1`) 등. 실제 펌웨어 소스·자체 작성 여부·실행 기능은 미확인.
- **전원부:** 2핀 배터리 단자(`CN1`), 인덕터 **22µH(`L1`)**와 `ME2188A50XG`(`U2`) 전원 IC, 관련 커패시터, Micro-USB 5핀(`USB1`). 회로도에서 **`C3`는 10µF이며 극성(+ 표기) 심볼**로 표시된다. 이 화면은 배터리 전원 경로의 단서지만 실제 제작품에 실장된 커패시터의 모델·방향까지 확증하지 않는다.
- **센서 연결용 접점:** 뒷면의 **가운데·좌측·우측에 센서를 연결**할 수 있게 설계했다는 사용자 진술. 회로도에는 `P1/P2/P3` 3패드 계열 접점이 존재한다.
- **펌웨어 업로드용 접점(2026-10-26 추가 진술):** `neoboard`에서처럼 **독립적인 6핀 ICSP/ISP 헤더를 실장하지 않고**, 추가로 필요한 업로드 신호를 **보드 뒷면의 별도 패드로 분산 배치**했다. 사용자가 보여 준 `PCB_nemotiny` 레이아웃에는 넓은 모듈 접점과 회로 배선 및 다른 패드가 보이지만, **각 업로드 패드의 정확한 MOSI/MISO/SCK/RESET/VCC/GND 매핑과 실제 프로그램 기록 성공은 자료만으로 미확정**이다. **센서 연결 패드와 업로드 신호용 패드를 동일한 기능으로 묶지 않는다.**
- **BOM 일부 확인:** `ATTINY85-20SU`(`U1`, LCSC `C89852`), `ME2188A50XG`(`U2`, `C236769`), 22µH 인덕터(`L1`, `C361669`), `C3` 10µF(`C129234`), `C4` 100µF(`C122251`), Micro-USB(`C482361`), `SW1`(`C381038`)가 화면에 표시된다. **현 시점에 표시되는 BOM의 가격과 실제 당시 구매/발주 단가를 혼동하지 않는다.**
- **레이아웃:** `PCB_nemotiny`와 `PCB_nemotiny_a`의 서로 다른 두 버전이 보인다. 다각형 외곽/실크스크린 로고, 하단 USB, 중앙 MCU와 모듈 접점의 기본 배치는 유지되며, 대안 `_a`는 넓은 구리 포어(copper pour) 영역이 표시된다. **구리 포어가 정확히 어떤 net에 연결됐는지는 레이어 색과 사용자 설명만으로 확정하지 않고 원본 검증을 필요로 한다.**

### Paperware 마지막 모터 모듈 — `nemomotor_connector` / `nemomotor_mounted` (2026-10-26)

**프로젝트·결과(C: 사용자 직접 확인):** 두 설계는 **Paperware용 신규 모터 모듈**로 개발했다. **둘 다 실제 PCB 발주·제작·실장·동작 검증은 하지 않았으며, 모터 모듈을 설계한 이후 Paperware 프로젝트가 종료**됐다. 프로젝트 종료 연월, 제품 출시 여부와 장기간 조직 운영은 이번 발언만으로 확대하지 않는다.

| 항목 | `nemomotor_connector` | `nemomotor_mounted` |
|---|---|---|
| 역할 | 2핀 커넥터를 통한 **외부 모터 연결형** | 모터 풋프린트를 PCB 측에 직접 배치한 **모터 장착형** |
| 회로 | `FM116C` 모터 구동 IC (부품 `R1`), `CN1` 2핀, `H1` 4핀, 100nF(`C1/C2`) ×2, LED·200Ω 저항 | `FM116C`, 모터 `M1`, `H1` 4핀, 100nF(`C1/C2`) ×2, LED·150Ω 저항 |
| PCB | 4개 넓은 접점, 상단 양측 홈, 로고, 커넥터 풋프린트 | 4개 넓은 접점, 상단 양측 홈, 로고, 외측 모터 풋프린트 및 연결 패드 |
| 산출물 | EasyEDA 회로도, PCB 레이아웃, BOM 스크린샷 확인 | EasyEDA 회로도, PCB 레이아웃, BOM 스크린샷 확인 |
| 결과 | **설계만 진행, 시제품 미제작** | **설계만 진행, 시제품 미제작** |

**원본에서 보이는 부품(A: 스크린샷):** `nemomotor_connector` BOM은 `FM116C`(LCSC `C2802264`), `1251SMT-2P` 모터 커넥터(`C132528`), 4핀 헤더(`C124378`), 100nF 2개(`C1525`), `XL-1005SURC` 표시 LED(`C965790`), 200Ω을 표시한다. `nemomotor_mounted` BOM은 `FM116C`, `M1/MOTOR`(구체 부품번호 공란), 100nF 2개, `H1` 4핀, 표시 LED(`C779449`), 150Ω을 표시한다. **실제 부품 구매·모터 제원·구동 성공은 이 목록으로 입증할 수 없다.** PCB 화면의 레이어/배선은 최종 전기적 정확성을 입증하지 않으며, 특히 장착형 PCB에는 연결 가이드처럼 보이는 선이 남아 있어 라우팅 완료/DRC 합격을 확정할 수 없다.

**상황 → 문제 → 판단 → 조치 → 결과 (이력서 보조 사례용 초안):**

- **상황:** 기존 Paperware의 카드보드·구리박 테이프 기반 모듈을 NeoPixel 이외의 모터 구동으로 확장할 구상이 있었다.
- **문제/목표:** 카드보드 접점 구조에 맞게 모터를 연결하거나 직접 장착할 수 있는 별도 구동 모듈이 필요했다.
- **판단:** 모터를 별도 2핀 커넥터로 연결하는 방식과 모터를 보드에 직접 배치하는 방식을 **각각 별도 설계안**으로 비교했다. 다만 어떤 비교시험이나 정량적인 선정이 실제로 진행됐다는 근거는 없다.
- **조치:** FM116C 구동 IC와 외부 제어 단자, 보드 접점·모터 장착 영역을 EasyEDA 회로도/PCB에 반영하고 BOM을 구성했다.
- **결과:** **실제 발주·제작하지 않은 설계 산출물 2건을 남긴 채 프로젝트 종료**. 특정 모터를 정상 구동했다거나 완성된 모듈로 납품했다고 기재하지 않는다.

**경계:** 이 2개 모터 보드는 2018년 카드보드 드론의 모터 구동 실패와 다른 시기/회로의 작업이다. 둘을 하나의 제어기나 실패-해결 사례로 연결하지 않는다. 발주한 NeoPixel PCB의 시제품 경험과도 분리한다. 관련 상세 목록은 [Paperware](paperware.md) 참고.

## 기술적으로 확인한 소스

### 2018 micro:bit MicroPython — `controller.py` (**본인 직접 작성, 사용자 확인**)

- A/B 버튼 조합을 `U`(up), `D`(down), `S`(stop) 라디오 메시지로 전송.
- 버튼을 누르지 않을 때 가속도 센서 X/Y값을 읽고 절댓값 70 이하는 0으로 간주하여 미세 움직임을 제거.
- 두 축 값의 자릿수 길이를 붙인 문자열로 전송하고, 5×5 LED matrix에 상하좌우/대각 방향 표시.
- `radio_test.py`는 명령 수신 후 LED 방향 표시를 수행함. 이 파일은 발신 `controller.py`의 동작을 수신측에서 확인하려는 테스트 구현으로 해석 가능하지만, **이 파일의 개인 작성 여부와 실제 통신 성공은 확인되지 않음**.
- **검증 경계:** 직접 구현이 확인된 것은 컨트롤러 송신·입력 처리 부분이다. 드론 자체의 제어기 구현이나 비행 완료까지 증명하지 않음.

### 2018 드론 기체 제작·조종 시도 — 사용자 직접 확인 (2026-10-24)

- **상황:** 카드보드와 부품을 이용해 실제 드론 기체를 만들고, 직접 만든 micro:bit 컨트롤러로 조종을 시도했다.
- **문제:** 사용자의 당시 관찰/판단에 따르면 카드보드 프레임과 부품의 무게에 비해 모터의 추진력이 부족했다. 무게·추력·전류의 실측 데이터는 확보하지 못했다.
- **판단/조치:** 직접 구현한 버튼/기울기 기반 무선 컨트롤러를 활용해 제작 기체의 조종을 시도했다. 기체의 구체적인 설계 변경·모터 교체 등 추가 대응은 확인되지 않았으므로 기재하지 않는다.
- **결과:** **이륙 실패.** 기체를 실제로 제작해 시도한 경험은 확인됐으나 무선 명령이 수신되어 모터에 반영됐는지, 지상 동작 확인의 세부 범위는 아직 알 수 없다.
- **배운 점으로 활용할 해석(후속 면접용, 사실/추론 구분):** 임베디드 SW 구현만으로 완성되지 않는 물리 시스템의 제약(하중·추력 등)을 보여 주는 사례. 다만 당시 본인의 구체적 판단·회고를 별도로 확인하기 전에는 특정 교훈을 당시에 의식했다고 단정하지 않는다.

**경험기술서 잠정 문장:** “micro:bit의 버튼·가속도 입력을 무선 명령으로 변환하는 MicroPython 컨트롤러를 직접 구현하고, 카드보드 기반 드론 기체를 제작해 조종을 시도했습니다. 기체·부품 무게에 비해 모터 추진력이 부족해 이륙에는 실패했으며, 기체 제어용 Arduino 코드는 드론 관련 서적의 제공 예제를 활용했습니다.”

### 고교 Arduino 드론 교재·키트 실습 — `drone.ino` (**도서 제공 예제, 개인 저작물 아님**)

**출처/기여 구분:** 2026-10-24 사용자가 `drone.ino`를 **도서 제공 자료**라고 확인했으며, **2026-10-29에는 고등학생 때 Arduino 드론 교재와 키트를 직접 구매해 조립·실행하며 원리를 익혔고, 이 경험이 후속 Paperware 드론의 기반이 됐다고 재확인**했다. 아래는 코드에 포함된 **참고 기술 구성**일 뿐 PID 제어기·IMU 필터·Arduino 비행제어 소프트웨어를 직접 구현한 이력으로 사용할 수 없다. **고교 Arduino 교재 기체와 후속 Paperware 카드보드 기체는 별도**이며, 후자의 이륙 실패를 전자의 결과라고 해석하지 않는다. 정확한 도서명·예제 라이선스·키트 비행 결과는 미확인. ## 이력서 선별 시 권장 구조

1. **Paperware PCB 개선:** 2022년 당시 발표와 이후 회고, 2026-10-26 사용자 직접 확인을 대조. **2021년경 EasyEDA NeoPixel PCB 직접 설계, LCSC 가격 비교·부품 선정, JLCPCB 발주 및 실제 활용**을 확인한 경험. [Paperware 상세 원장](paperware.md) 참고. 초기 `test`와 **첫 발주 `neopixel`의 EasyEDA 회로도·PCB·BOM 화면을 확인**. `neopixel`은 WS2812C 9개를 3×3 배열한 보드이며, **JLCPCB PCB 제조 발주 후 별도 부품을 직접 납땜**했다고 사용자가 확인했다. **후속 `nemopixel`은 WS2812E 8개, 클립 홈, 로고, 자동조립을 적용했고 납 잔류 문제를 관찰한 것으로 확인**. **`nemopixel_rev2`는 XL-5050RGBC-WS2812B 8개로 부품 교체·외형 수정 후 크림납/스텐실/열풍 실장을 시도했지만 실제로는 인두 수동 납땜으로 마무리했다고 확인**. 최종 적용판/주문 증빙/점등 실측은 아직 미확인.
2. **micro:bit 무선 컨트롤러·드론 제작 시도:** `controller.py` 직접 구현에 따라 **버튼/가속도 입력 처리 → 라디오 명령 패킷 전송 → LED 상태 표시**를 개인 SW 사례로 분리할 수 있음. 제작 기체의 **추력 부족에 따른 이륙 실패**를 결과로 명시하며, **책의 `drone.ino` 내부 알고리즘은 기여 실적에서 제외.**
3. **2019 Paperware 계열 WCRC 출품 스마트 타이머 무드등:** **진행하던 Paperware를 micro:bit 대회에 출품한 것**이며 신규 독립 프로젝트로 중복 계산하지 않음(2026-10-29 사용자 직접 회고). **전체 SW 직접 구현**(타이머/기울기/NeoPixel/radio)은 별도 기술 기여로 확인된다. 기울기 갱신 문제 수정, 라이브러리 충돌 우회 기록과 당시 수상 기록을 연결하되 최종 통신 동작은 미확정. **경쟁 작품이 적었다는 당시 개인 인식은 객관적 경쟁률 자료와 구별하며 수상만으로 기술적 우월성을 추론하지 않음.**
4. **2020 micro:bit 교육용 코드 개발:** 기초 LED/버튼부터 센서·서보·NeoPixel 응용까지 **예제 프로그램을 직접 작성**하고, **2019년 1월 무드등 코딩 튜토리얼 영상 1개를 제작**(`무드등 코딩영상.MP4` 및 `무드등 코딩영상 2차편집.MP4`와 관련 편집 원본 발견; 2차 편집 MP4가 최종본 유력 후보(사용자 기억), 공개 여부 미확정). **강의/교육 운영은 하지 않았고 PPT·기타 교육자료 제작에도 참여하지 않았으므로** 이력서에는 코드 개발과 확인된 영상 작업만 기재한다.
5. **Link Cube automata 및 조별 구현예시:** 기술 산출물은 확인했으나 개인 저작 미확정으로 구분.

**2026-10-27 EasyEDA 설계 정리:** `nemomotor_connector`와 `nemomotor_mounted`는 Paperware의 신규 모터 모듈로 설계했지만 **둘 다 발주·제작 전에 프로젝트가 종료**됐다고 사용자 확인. 각 회로도·PCB·BOM 화면도 확인했다. `neoboard`는 ATtiny + NeoPixel 통합 보드의 실물 제작·일부 수리 경험, `nemotiny`는 micro:bit 대체 ATtiny85 제어보드의 실물 제작·배터리 과열·USB 간섭·미발주 대안까지 정리했다. `nemotiny`에는 독립적인 ICSP 헤더가 없고 **프로그래밍용 신호를 후면 패드로 배치**했다. `neoboard`와 `nemotiny`를 Paperware의 실제 완성품으로 자동 귀속하거나 참고 ATtiny 회로/펌웨어의 원작 개발자로 주장하지 않는다. **Paperware 경험은 [최종 정리본](paperware.md)에서 서술하고, 여기서는 서로 다른 설계의 근거와 귀속 경계를 보존한다.**

**2026-10-26 후속 확인 — `nemotiny` 업로드 패드:** 사용자가 `PCB_nemotiny` 후면 패드 레이아웃 화면을 제공하면서, **별도 6핀 ICSP 헤더를 만들지 않고 펌웨어 업로드를 위한 추가 핀을 뒷면 패드로 배치**했다고 확인했다. 이는 `neoboard`의 2×3 물리 헤더와 구분된다. **정확한 핀맵·프로그래밍 성공은 미확인**이다.

**2021년경 PCB 작업에 대한 추가 근거:** 2022.04 진로활동 발표 `초안.pptx`는 “작년, 복학하기 전에” Paperware용 PCB 모듈 개발과 납땜 진입장벽 완화 목적을 당시의 표현으로 설명한다. `PCB/`로 보관된 Drive 폴더는 파일 수정 기록이 대부분 2018년인 OrCAD 설치·부품/데이터시트 참고자료이며, 이번 조사에서 **2021년 NeoPixel 모듈의 특정 CAD/Gerber/발주 원본이라고 식별하지 못했다**. 2026-10-26 사용자가 NeoPixel 모듈 PCB 직접 설계·주문·사용을 재확인했으며, **EasyEDA 설계·LCSC 부품 가격 비교 및 선정·JLCPCB 발주** 경로도 추가로 확인했다. 단, 업체 계정에 해당 프로젝트·견적·주문 데이터가 남아 있는지는 아직 확인하지 못했다.
