## 2. 정적 코드 구분 — 개별 기능과 실제 통합

### 2.1 Pygame 메인 화면 — `GIF/main.py`

- `pygame.display.set_mode((570, 400), FULLSCREEN)`, `normal/smile/angry` 3개 표정, 각 표정의 눈·입 **4프레임 이미지**, `balgre.png`, `smile.mp3`·`angry.mp3` 등 로딩 로직.
- **센서 시리얼/Arduino 탐색과 `require('B')`·`require('D')` 호출 부분이 큰 주석 블록**으로 남아 있음. 활성 루프 내 `next_emotion = normal` 상태를 센서로 변경하지 않으며, `phase == 0`에서 `emotion = next_emotion`을 대입하는 구조. 이 저장 버전의 얼굴 표정은 **센서에 의해 전환되지 않음**.
- `randint(1, 20)`를 통한 임의의 프레임 진행, Pygame 음향 재생 코드가 있음. **표정 UI 자체의 실기 구동 결과는 미검증**.

### 2.2 다른 버전 — `GIF5/pygameTest/main.py`

- 같은 표정 이미지/음악 루프 구조의 **다른 저장 버전**이지만, 센서 시리얼 연결 구문은 아예 활성 코드에서 빠져 있음.
- `emotion = angry`, `next_emotion = normal`을 선언해 두고 **`#emotion = next_emotion`로 상태 대입을 주석 처리**. 이 버전도 **센서값에 반응하는 UI가 아니다**.
- **중요:** `GIF/main.py`에서는 normal 상태 고정, `GIF5/pygameTest/main.py`에서는 angry 상태 고정인 듯 보이나 **실제로 최종 발표한 버전/현장 구성은 모른다**. 서로 다른 버전의 정적 구조를 하나의 실행 로그처럼 합쳐 성공·실패 원인을 확정하지 않는다.

### 2.3 Arduino 센서 쪽 — `GIF5/sense/sense.ino`

- `CDS = A0`(조도 입력), `IR = 2`(적외선 디지털 입력)를 정의하고 시리얼 `9600`으로 동작하는 구조.
- 요청 `'B'`에 `analogRead(CDS) > 400`를 기준으로 `T`/`F`, 요청 `'D'`에 `digitalRead(IR)` 값의 반대를 `T`/`F`로 전송. 그 외에는 `E`를 보냄.
- `B`/`D`의 의미를 밝음/어둠·건조/습윤 등 **추측으로 단정하지 않는다**. **D는 IR 디지털 핀**으로 제어되어 있으며, 이것만으로 토양 수분 센서·자동 급수 시스템이 있었다고 주장하면 안 된다.

### 2.4 Raspberry Pi 직렬 통신 시험 — `GIF/test.py`, `GIF5/serial/test.py`

- `/dev/ttyACM0~9`와 `/dev/ttyUSB0~9` 경로 탐색 → `serial.Serial(path, 9600)` → `require('B')`·`require('D')` 요청.
- 시리얼 결과의 첫 문자를 `T`/`F`로 읽고 `angry`/`smile`/`normal`을 **print하는 독립 실험**.
- **시리얼 통신 시험 코드**가 존재한다는 사실만으로 **실제 표정 UI와 연결된 종단 간(End-to-End) 작동 검증에 성공했다고 할 수 없다**.

### 2.5 온습도·ADC·초음파 및 기본 GUI/소리 시험

| 파일 | 코드에서 보이는 역할 | 미확인/주의 |
|---|---|---|
| `GIF/readDHT.py` | `Adafruit_DHT.DHT11`로 습도·온도 읽고 로그 출력 | 메인 UI와 결합한 증거 없음. 식물 토양 수분과 대기 습도를 혼동 금지 |
| `GIF/ADC0832.py` + `analogRead.py` | GPIO로 ADC0832 직렬 데이터를 읽고 MSB/LSB 계산치 비교 후 `None` 반환 가능, 독립적인 아날로그 입력 시험 | 어떤 실제 센서가 ADC에 연결됐는지, 측정 성공률은 불명. **파일별 저자 미확정** |
| `GIF/UltraSonicDistance.py` + `readUSD.py` | Trig/Echo pulse 길이로 거리 추정하는 독립 시험 | 식물의 성장 길이 측정에 썼다 등 활용 목적 확정 금지 |
| `GIF5/USD/USD.ino` | 초음파의 `trig`를 `INPUT`, `echo`를 `OUTPUT`으로 초기화하면서, 아래에서는 `digitalWrite(trig)`·`pulseIn(echo)`를 호출함 | **핀 입출력 방향이 사용 의도와 반대인 정적 불일치로 보임**. 버그 후보일 뿐 당시 고장 원인이나 최종 코드 채택 사실 확정 금지 |
| `GIF/pygame_1/2/3.py`·`animate.py` | 창, 이미지, 애니메이션, 이벤트 루프 각각 시험 | 정상 통합 제품 성공 지표 아님 |
| `GIF/playsound.py`·`playsound2.py` | Pygame mixer로 MP3 1개/2개를 순서대로 재생하는 실험 | 현장 소리 동작/오디오 시스템 안정성 확인 불가 |

## 3. ‘테스트 중요성’의 정확한 교훈

### 직접 뒷받침할 수 있는 내용

- **C1 본인 회고:** 여러 코드를 작성했으나 장치의 실제 동작이 좋지 않았고, **테스트가 중요하다고 느꼈다**.
- **A1/A2 소스:** 단일 기능을 대상으로 한 시험 스크립트가 많이 존재한다. Pygame 메인 코드에 센서 입력이 **통합되지 않은 저장 버전**이 확인되고, Arduino 쪽에는 이를 받아 줄 요청·응답 구현이 따로 있다.
- 이는 **개별 기능 구현 → 입출력/프로토콜 연동 → UI 상태 전이 → 실제 하드웨어 시연**을 각 단계에서 검증해야 한다는 실무적 시사점을 제공한다.

### 근거가 없으므로 금지할 주장

- '단위 테스트·통합 테스트를 구축해 실패율을 00% 개선했다.'
- '원인은 통신 동기화 버그/특정 GPIO 배선 오류로 밝혀져 수정 완료했다.'
- '센서와 표정, 자동 급수가 실제 현장에서 모두 연동되었다.'
- '최종 하드웨어 정상 운영, 수상, 제품 출시, 실제 사용자 만족도 평가를 했다.'
- '모든 파일을 개인이 직접 단독으로 작성했다.'

### 프로젝트별 시간 경계

- **2019 버디팟**: 실패·테스트 중요성을 **체감한 경험**. 학습 내용은 본인 회고로 확인된다.
- **2021+ 다른 프로젝트에서 체계적 테스트를 도입한 사례**는 별도 소스(예: 각 프로젝트의 테스트·PR·로그)로 확인되는 경우에만 연결. 이후 학습 방향의 인과관계를 과도하게 단정하지 않는다.

## 4. 미확인 항목과 향후 회고

1. 개인 작성 파일/기여가 주로 센서·통신·Pygame 중 어느 영역이었는지. 지금은 **여러 코드를 작성했다는 회고**만 직접 확인.
2. 실제 시제품(식물·케이스·디스플레이)의 완성 형태와, 시연 당시에 **어떤 입력/출력이 특히 동작하지 않았는지**.
3. 원본 `GIF`와 `GIF5` 중 **최종 제출 당시 버전이 무엇인지**. 일부 파일은 연습·실험/동일 이름의 복사본일 수 있다.
4. 2019 GIF에 참가한 팀 이름과 발표·평가 결과. 보존된 행사 사진은 활동 맥락일 뿐 팀 수상 증빙이 아니다.

**정리 결론:** **코드를 작성한 경험 + 하드웨어 통합 동작 실패의 경험 + 이후 중요하게 여긴 테스트 관점**이 핵심이다. 능동적으로 테스트 체계를 구축해 성과를 낸 사례로 바꾸어 쓰지 않는다.
