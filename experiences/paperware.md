# Paperware — micro:bit 메이커 키트 및 커스텀 PCB

> **자료 재조사 상태 (2026-10-26):** 2022년 당시 발표자료 원문과 2026-10-26 사용자 재확인에 따라 **2021년경 Paperware용 NeoPixel PCB를 직접 설계·발주·실제 사용**한 사실을 기록한다. 다만 2018~2019년 초기 사업과 군 복무 이후 PCB 모듈 작업이 하나의 연속 프로젝트인지 **미확정**이다. 이를 확인하기 전까지 전체 기간이나 모든 산출물을 한 사람의 일관된 개발 성과로 묶지 않는다.

## 한 줄 요약

micro:bit와 카드보드·구리박 테이프를 활용한 코딩/메이킹 교육 키트 활동에서, 납땜을 전제로 한 기존 NeoPixel 모듈의 불편함을 해결하기 위해 카드보드 회로에 맞는 넓은 접점의 커스텀 PCB를 설계하고 시제품을 발주해 무드등 제작에 적용한 경험이다. 이 PCB 작업은 **2022년 당시 발표자료·이후 회고·2026-10-26 사용자 직접 재확인**에 근거한다. **2026-10-26 추가 직접 진술:** EasyEDA에서 설계하고, LCSC에서 부품별 가격을 비교해 선정한 뒤 JLCPCB에 제조를 발주했다. **EasyEDA 계정에서 첫 가능성 검증용 `test` / `PCB_test` 프로젝트의 회로도·PCB 레이아웃·BOM 화면이 실제로 남아 있음을 2026-10-26 사용자 스크린샷으로 확인**했다. 다만 화면 캡처가 프로젝트 원본 파일 다운로드나 최종 납품 버전 확인에 해당하는 것은 아니다. **실제 발주했던 첫 설계인 `neopixel`의 회로도·PCB·BOM 화면도 2026-10-26 확보했고, 부품을 별도 구매하여 직접 납땜했다는 사용자 진술도 확인했다.** **후속 `nemopixel` 설계(2021-10-03 회로도 날짜 표시)**도 회로도·PCB 두 레이아웃·BOM으로 확인했다. **자동조립(PCBA)을 이용했고 이후 뒷면 대형 패드와 홀 주변에 납이 남는 문제를 실제 관찰**했다고 사용자가 설명했다. `nemopixel`의 원형 LED 배열안은 채택하지 않았다. **실제 `nemopixel_rev2` 프로젝트도 추가 발견**했다(회로도 날짜 **2021-12-28**). 8 LED 설계에서 부품을 한 번 더 교체했고, 하단 모서리 외형을 수정했으며, 크림납·금속 스텐실·열풍기 방식의 실장을 시도했지만 판 크기 문제로 **인두를 이용해 직접 납땜**했다고 기억한다. 다만 리플로 납땜을 성공적으로 마쳤거나 PCBA 외주를 재이용했다고 주장하지 않는다. CAD/Gerber 원본 내보내기·JLCPCB 발주 영수증·전기적 시험 기록은 아직 미확인이다.

## 2. 핵심 경험 — 상황 → 문제 → 판단 → 조치 → 결과

### 상황

micro:bit를 카드보드 및 구리박 테이프 기반 회로와 연결해 사용자가 직접 조립하고 코딩하는 교육용 메이커 키트를 제작했다. 카드보드의 가공 용이성, 낮은 재료 부담과 모듈 조합을 통한 확장성이 제품 기획의 주요 방향이었다. 2018년 팀 발표에는 드론형 제작 사례가, 후속 개인 회고에는 무드등 제작 사례가 남아 있다.

### 문제

기존 NeoPixel 모듈은 납땜이 필요한 연결 구조라 구리박 테이프와 카드보드를 활용한 키트에서 쉽게 연결하기 어려웠다. 교육용 조립 과정에서 사용할 수 있는 접점·연결 방식이 필요했다.

이는 **2022년 진로활동 발표와 당시 회고**에 남긴 문제 인식이다. 납땜 과정의 시간·실패율을 정량 측정한 기록은 현재 확인되지 않는다.

### 판단

기존 모듈 사용법을 복잡하게 안내하는 대신 카드보드 회로에 직접 닿는 **커스텀 PCB의 접점 형상**을 바꾸는 방향을 선택했다. 고등학생 시절 스스로 익혔던 PCB 설계 경험을 활용해, 제품의 교육적 목적에 맞게 하드웨어 연결 구조 자체를 조정하려 했다.

### 조치

- **EasyEDA에서** 카드보드 회로와 접촉할 수 있도록 접점을 넓힌 NeoPixel PCB를 단계적으로 설계 (**`test`, `neopixel`, `nemopixel`, `nemopixel_rev2`의 회로도·PCB/BOM 화면 확인**). 후속 `nemopixel`에서는 클립 연결을 위한 상단 양쪽 홈·로고 디자인과 자동조립 목적의 홀 2개를 추가
- **LCSC에서 부품 후보 가격을 직접 비교해 선정** (**`test`, `neopixel`, `nemopixel`의 BOM 화면 확인; 신형 WS2812E 및 커패시터 부품번호는 후속판 화면에서 확인, 당시 구매 단가는 미확인**)
- **JLCPCB에 PCB 제조 발주**. 첫 실제 발주판 `neopixel`의 소자는 별도 구매해 직접 납땜 실장 (**PCBA 외주 아님**)
- **후속 `nemopixel`의 자동조립 서비스 이용** (사용자 직접 진술). 제조·조립 후 **후면 넓은 패드의 굳은 납으로 인한 표면 요철**, **홀 주변의 납 잔류**를 관찰하고 이를 후속 개선의 문제로 확인. **홀 설계가 원인인지는 미검증**
- **`nemopixel`의 원형 LED 배열도 설계했으나 사용하지 않기로 결정** (PCB 레이아웃 2종 확인; 두 번째 배열안의 실제 발주·실사용을 주장하지 않음)
- **`nemopixel_rev2`에서 부품 교체 및 하단 모서리 형상 수정**. 금속 스텐실을 이용한 크림납 도포·열풍 리플로 방식도 시도했으나 **판 크기 문제로 인두 수동 납땜으로 전환** (방식 명칭은 당시 설명에 대한 기술적 해석이며, 정확한 판 종류·사용 과정은 미확인)
- 제작된 NeoPixel 모듈을 Paperware 무드등에 실제 적용 (**2026-10-26 사용자 재확인**)
- Paperware 확장 모듈로 **모터용 `nemomotor_connector`와 `nemomotor_mounted` 2종을 EasyEDA에서 회로도·PCB 레이아웃·BOM까지 설계**. 첫 번째는 **2핀 커넥터로 모터를 외부 연결**하는 방식, 두 번째는 **모터 풋프린트를 PCB에 직접 배치**하는 방식

**2026-10-26 사용자 직접 확인:** 이 두 모터 모듈은 **둘 다 실제 발주·제작하지 않았으며, 설계를 마친 뒤 Paperware 프로젝트가 종료됐다.** 제작·동작 검증·보급으로 확대하지 않는다.

### 결과

**NeoPixel PCB를 직접 설계하고 발주해 실제 무드등에 사용한 경험**을 사용자가 재확인했다. **최초 발주된 `neopixel`에서는 부품을 따로 구매·직접 납땜했으며, 후속 `nemopixel`에서는 자동조립 서비스까지 이용했다고 설명했다.** 자동조립 후 대형 후면 패드와 홀 주변에 남은 납 문제를 관찰했지만 원인 분석·수정 성공은 별도 미확인이다. **이후 `nemopixel_rev2`로 한 번 더 부품을 바꾸고 외형을 다듬었으며, 크림납·스텐실·열풍기 방법을 시도하다 결국 인두 납땜으로 마무리했다고 기억한다.** 이 버전이 앞선 납 잔류 문제를 실제로 해결했는지, 최종 사용된 판본인지는 확인하지 못했다. 납땜이 필요 없도록 하려던 부분은 **최종 사용자의 카드보드·구리박 테이프와 모듈 사이 연결**에 관한 설계 취지이지, 시제품 제조 과정에서 납땜을 전혀 하지 않았다는 의미가 아니다. 2022년 당시 발표에도 Paperware용 PCB 모듈 개발 내용이 기록돼 있다. 다만 사용자 테스트, 납땜 작업 감소율, 교육 효과, 판매량, 최종 양산·보급 여부는 확인된 자료가 없다. 따라서 결과는 **커스텀 모듈 설계와 제한된 시제품 적용**으로 표현한다.

### 2026-10-26 EasyEDA 초기 가능성 검증용 `test` 보드 — 실사용 최종판과 구분

**자료 성격:** 사용자 업로드 EasyEDA 계정 화면 3장. 사용자는 `test`가 최초 가능성 검증용, **`neopixel`이 첫 실제 발주판, `nemopixel`이 그다음 개선판**이라고 각각 확인했다. 이전 조사 중 언급한 `neopixel_rev2`는 실제 프로젝트명을 잘못 추정한 것이고, **`nemopixel` 다음 버전으로 실제 `nemopixel_rev2` 프로젝트가 새로 확인**됐다. 서로 별도의 프로젝트이다. 각 판의 실제 제조/실사용 범위는 아래대로 구분한다.

- **회로도:** `test`/`Sheet_1`에서 주소 지정 RGB LED 3개(`LED1~3`), `C1~3` 100nF 커패시터와 3핀 연결부(`P1`/`P3` 표시)를 볼 수 있다. PCB와 부품 데이터는 이 스크린샷으로 정적 확인했으며 통전·동작 시험 결과는 확인하지 못했다.
- **PCB 레이아웃:** `PCB_test`에는 LED 3개 및 관련 부품과 상단 **넓은 사각형 접점 패드 3개**, 배선/보드 외곽선이 표시된다. 접점의 의도가 카드보드용 구리박 테이프 연결이라는 사용자 회고와 잘 맞지만 **실제 접촉 검증과 최종 설계 치수는 미확인**이다.
- **BOM:** 화면 표의 `C1,C2,C3` 100nF(0402) 3개, LCSC `C41851`, 표시 단가 `0.007`; `LED1,LED2,LED3` XL-5050RGB 계열 3개, LCSC `C2843785`, 표시 단가 `0.056`; `P1` 3핀 연결 항목 1개(부품번호/단가 공란). **가격 통화 및 역사적 시점은 화면만으로 입증되지 않음**; 당시 최종 선정·주문 BOM으로 재해석하지 않는다.
- **검증 단계:** 이 자료는 **초기 설계와 BOM 작성 흔적(A: 화면)**을 확인하는 증거. 첫 보드의 실제 제조 여부, LED 점등 성공 여부, 이후 Rev 설계와의 변경점, 최종 발주판 및 전체 프로젝트의 성공 범위는 추가 확인이 필요하다.
- **공개 저장소 보안:** 공개 문서에 계정 식별자, 원본 프로젝트 ID/편집 URL, 부품 구매 내역의 개인정보 및 스크린샷 원본을 그대로 복제하지 않는다. 보관 자료는 사용자 제공 스크린샷을 기준으로 별도 추적한다.

### 2026-10-26 EasyEDA 첫 실제 발주 설계 `neopixel` — 별도 부품 구매·직접 납땜

**단계 확정(사용자 진술):** `test` 다음에 제작한 `neopixel` / `PCB_neopixel` 프로젝트는 **실제로 JLCPCB에 첫 번째로 발주한 PCB 설계**다. 부품은 따로 구입해 **사용자가 직접 납땜하여 실장**했다고 기억한다. 이 버전의 생산·조립 방식은 *PCB 외부 제조 + 부품 별도 조달 + 수작업 실장*으로 분리한다. **JLCPCB PCBA 서비스에 첫 보드의 조립을 외주했다고 주장하지 않는다.**

- **회로도(화면 확인):** `LED1~LED9`의 **WS2812C 주소 지정 RGB LED 9개**, 대응 `C1~C9` **0.1µF(100nF) 커패시터 9개**, 3핀 점퍼 `JP1`과 VCC/GND 연결. 회로 배선의 실제 점등/신호 품질을 검증한 자료는 아님.

- 전선이 꺾이거나 교차하는 문제에 대해 스티커형 flat cable 구조를 구상함.
- 제안서의 역할 표기상 김재훈은 ‘코딩’에 해당하며, 실제 코드·작동 검증 산출물은 이 제안서만으로 확인되지 않는다.

2018 Paperware, 2019 Link Cube, 이후 NeoPixel PCB 작업은 사용자 중심 메이커 교육과 모듈 연결 방식이라는 공통 주제를 갖지만 **사업·제품·팀 관계는 아직 미확정**이다.

## 5. 이력서·포트폴리오 활용 후보

**상세 경험기술서용 문장 (잠정):**

> micro:bit 기반 카드보드·구리박 테이프 키트의 조립 연결 문제를 개선하기 위해 EasyEDA에서 NeoPixel 커스텀 PCB를 설계했습니다. 초기 3 LED 검증안을 9 LED(3×3) 모듈로 확장하고, LCSC에서 부품별 가격을 비교·선정한 뒤 JLCPCB에 PCB를 발주했습니다. 첫 발주판의 부품은 별도 구매해 직접 납땜했으며, 해당 개발 활동에서 제작한 모듈은 Paperware 무드등에 활용했습니다. (특정 Rev의 최종 실사용 여부는 추가 확인 필요)

**활용 위치:** SW/AI Backend 중심 이력서의 상단 핵심 성과보다는, 메이커·임베디드·HW/SW 융합 직무에서 **제약을 분석하고 소형 하드웨어를 개선한 보조 사례**가 적합하다.

**표현상 주의:**
- Paperware를 2018~2021년 단일 기간의 연속 개발 프로젝트로 단정하지 않는다.
- Link Cube 2019 제안 기능과 모터 PCB를 완제품으로 주장하지 않는다.
- 전체 키트·드론·코딩 플랫폼의 단독 구현을 주장하지 않는다.
- 납땜 감소, 정확성·신뢰성 향상, 사용자 만족 등 측정치가 없는 결과를 수치화하지 않는다.
- 15회 교육 실적을 Paperware의 단일 프로젝트 성과로 붙이지 않는다.

## 6. 현재 남은 조사 항목

1. **Paperware와 연관성 확인, 조직적 연속성 미확정:** 2021년경 NeoPixel PCB 작업을 Paperware 관련으로 사용자 확인. 2018년 최초 팀 활동과 동일한 프로젝트의 지속 개발인지, 재개·파생인지 아직 구분하지 않는다.
2. **당시 설계·발주 원본:** EasyEDA `test`(초기 검증), `neopixel`(첫 PCB 발주·직접 납땜), `nemopixel`(자동조립 경험), `nemopixel_rev2`(부품 교체·외형 수정·인두 실장)의 회로도/PCB/BOM 화면을 확인했다. **각진 모서리 중간 설계는 EasyEDA에 해당 버전 파일이 남아 있지 않은 것으로 보이지만 사용자가 실물 PCB는 보유 중이라고 재확인(2026-10-26)**. 보드 사진 촬영/현물 대조는 추후 진행하며 지금은 **설계 데이터 미복원·실물 보유(사용자 진술)**로 구분한다. 해당 보드를 별도의 제작 성과로 중복 산정하거나 제조 회차·세부 부품을 추정하지 않는다. `nemopixel_rev2`의 회로도에는 2021-12-28이 기재. **정확한 주문 상세·PCB 생산일·수량·Gerber, 실사용 최종판과 각 버전 LED 동작 시험**은 아직 미확정. 두 번째 판의 PCBA 서비스 이용과 이후 rev2의 직접 납땜을 구분한다.
3. **역할 분담:** 2018년 `controller.py` 직접 구현 및 카드보드 기체 제작·조종 시도·이륙 실패는 확인 완료. **무선 명령 수신/모터 반응 확인 범위**, 초기 기체의 개별 설계 담당, 2019 Link Cube 기획·코딩, 이후 PCB 설계의 추가 개인 책임은 각각 무엇이었는가?
4. **동작 검증:** 무드등에 실제 적용한 사실은 확인 완료. 전기적 연결·LED 동작 시험 범위와 보드 수정 반복 내역은 미확정.
5. **교육 실적:** 15회 교육이 어떤 프로그램에 귀속되는지 자료 확인이 필요한가? (본 프로젝트에는 현재 미귀속)

## 7. 네모감성 전체 폴더 추가 조사 (2026-10-24)

별도 사용자 보관 `네모감성/` 폴더를 확인해 **2018년의 micro:bit 무선 조종·드론 코드**, **2019년 Link Cube 기획/무드박스 제어자료와 HEX**, **2020년 micro:bit 교육 예제**를 추가 발굴했다.

`팀플/마이크로비트 코드/controller.py`에는 버튼 조합·가속도 X/Y값을 라디오 명령으로 변환하는 MicroPython 제어 코드가 있으며, **사용자가 직접 작성했다고 확인했다**. 다만 `팀플/drone/drone.ino`는 **드론 관련 도서에서 제공된 예제**로, 여기에 포함된 MPU6050 읽기·complementary filter·PID·모터 PWM 코드를 본인 직접 구현으로 주장하지 않는다. 수신 코드 `radio_test.py`의 작성자, **무선 명령 수신 및 모터 구동 확인 범위**, Paperware 프로젝트와의 관계는 아직 미확정이다. 반면 **실제 카드보드 기반 기체를 제작해 조종을 시도했으나 카드보드·부품 무게를 모터가 감당하지 못해 이륙에 실패한 사실**은 2026-10-24 사용자가 직접 확인했다. 이 실패 원인 설명은 당시 사용자 관찰에 따른 것이며 정량적인 중량·추력 측정으로 검증된 것은 아니다.

`다른코리아 미팅발표용.pptx`에 김재훈은 ‘코딩’ 담당으로, 2019년 `피티 제작.pptx`에는 CTO로 표기되어 있다. `추가 자료설명.pptx`에는 NeoPixel/기울기 기반 무드박스 제어를 설명하며, 관련 메인/컨트롤러 HEX가 존재한다. 이 사실은 기술적 역할을 좁히는 데 유용하지만 **최초 작성자·최종 작동·사업 성과를 증명하지는 않는다**.

초기 프로젝트를 분리한 전체 자료/소스 원장은 [네모감성 초기 메이커 증거 조사](nemogamsung-early-maker-evidence.md)에서 추적한다.
