## Link Cube 자동화 — 2019.12 v1 → 2020.01 v2

Intel HEX에 내장된 MakeCode 프로젝트 `main.ts`/`main.blocks`를 직접 추출해 **코드 동작 구조**를 비교했다.

| 항목 | `linkcube-automata-v1.hex` (2019-12-30) | `linkcube-automata-v2.hex` (2020-01-02) |
|---|---|---|
| 버튼 | A로 **조도 감지 mode=1**, B로 **흔들기 감지 mode=2** 중 한 모드 선택 | A와 B가 각각 **독립 상태 플래그 on/off**를 토글하고 LED 문자열 표시 |
| 센서 조건 | mode 1일 때 `input.lightLevel() < 40`, mode 2일 때 `input.isGesture(Shake)` | `(A==1 && lightLevel<80) || (B==1 && isGesture(Shake))` |
| 제어 대상 | P2 핀에 analog 1023 또는 0 출력 | P2 핀에 analog 1023 또는 0 출력, 루프에 `basic.pause(100)` |
| 변화의 의미 | 두 기능 중 하나 선택하는 구조 | 기능을 독립적으로 활성화하고 **OR 조건**으로 출력 제어. 조도 임계값도 40→80으로 조정 |

이 변화는 실제 코드에서 확인된다. 사용자가 의도했던 설계 이유, 어떤 기계장치를 실제로 구동했는지, 시제품 성공 여부, **해당 v1/v2 작성자**는 별도 확인이 필요하다. 소스 상 P2 아날로그 값 출력은 확인되지만 이것만으로 특정 모터·LED가 실제 켜졌다고 할 수 없다.

## 2020 교육 예제 — **본인 직접 작성 확인** 및 기술 단계

**작성자 확인(2026-10-25 사용자 진술):** `교육자료/examples/`의 번호별 예제와 기초반·심화반, 교육용 무드등 등 **교육 예제 코드**는 본인이 작성했다. `구현예시/`의 1·2·3조 파일은 작성자 기억이 없어 이 확인에 **포함하지 않는다**. 번호순 11개 예제의 파일 존재와 이름을 확인했고, 아래 **6개 파일은 원본 TypeScript 내용도 직접 복원**했다.

| 소스 | 코드에서 확인한 학습 기능 |
|---|---|
| `ex1-display` | LED 아이콘/직접 그린 패턴/이미지를 순서대로 표시하고 문자열 `Hello!` 출력 |
| `ex3-buttonif` | A/B/AB 버튼의 동시 입력과 조건 분기 |
| `ex8-accelerationmath` | X/Y 가속도에서 `atan2`와 `π/4` 구간을 이용해 **8방향 화살표** 산출 |
| `ex9-servo` | A/B 버튼으로 서보 각도를 **30°씩 감소/증가**, P2 핀으로 각도 출력(초기 90°) |
| `ex10-neopixel` | 버튼 A/B로 **빨강~보라 7색 배열**의 인덱스를 순환하고 P2의 8채널 NeoPixel RGB 색 출력 |
| `ex11-neopixelmap` | `Math.map`과 인덱스 0~899로 **RGB 그라데이션** 연산, NeoPixel 8채널 색 제어 |

나머지 `ex2-button`, `ex4-light`, `ex5-magnetic`, `ex6-magneticlist`, `ex7-acceleration`은 **파일 제목과 위치까지 확인**했으며 이번 단계에서 각 원본 코드를 모두 개별 분석했다고 주장하지 않는다.

수준별 폴더에는 `기초반`: 출력·버튼·기울기/서보/NeoPixel 관련 코드, `심화반`: 조도·자기장·가속도 수학·NeoPixel 색상 매핑 관련 코드가 존재한다. `예제.pptx`에선 **기본 출력, 버튼 입력, 가속도 센서** 슬라이드 구획을 텍스트로 확인했다. **예제 코드는 본인 작성이지만, 교안 PPT와 기타 비코드 교육자료의 제작자는 본인이 아니라고 직접 확인했다.** 자료 존재는 수업 진행을 뜻하지 않으며, 사용자 본인은 교육을 진행하지 않았다.

### 교육용 무드등 변형

`교육자료/moodlight/microbit-moodlight-2.hex`의 내장 `main.ts`를 확인했다. 12채널 NeoPixel을 P2에 연결한 설정, A/B 버튼으로 밝기 10씩 증감(범위 가드), 가속도 X/Y/Z의 ±512 기준에 따라 RGB색 또는 소등을 선택하는 분기가 존재한다. 같은 폴더에는 `1`, `2`, `3`, `4`, `1-1`, `2-1` 변형이 있어 **응용 콘텐츠를 단계별로 준비한 흔적**이 있으나, 단계별 수업 진행·최종 기체 동작은 미확인이다.

### 조별 `구현예시` 3개 — 소스 복원 확인

`microbit-1조.hex`, `2조.hex`, `3조.hex`의 MakeCode 내장 `main.ts`를 복원해 다음 로직을 확인했다.

- **1조:** 조도 < 40인 동안 P2 디지털 출력과 P0 서보 제어(각도 0~180°, 30° 단계에서 방향 반전); 밝으면 출력을 끄고 서보를 90°로 초기화.
- **2조:** A 버튼은 P2 아날로그 출력 1023 및 P1 디지털 출력 1, B 버튼은 두 출력을 0으로 설정.
- **3조:** 온도 < 10 / > 40, P0 아날로그 입력 < 400 / > 800에 따라 8채널 NeoPixel 색상 및 micro:bit LED 얼굴 아이콘을 전환.

**의미:** 같은 날짜(2020-01-19)에 3개의 서로 다른 센서·액추에이터 응용 코드가 그룹명으로 보관됐다. 사용자도 오래되어 파일의 출처와 작성자를 기억하지 못한다고 밝혔으므로 **작성자·학생 산출물 여부를 모두 미확정으로 유지**한다. 교육 예제 코드 전체의 개인 저작 확인과 혼동하지 않는다.
