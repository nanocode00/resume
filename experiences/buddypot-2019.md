# 2019 GIF ‘버디팟(BuddyPot)’ — Raspberry Pi 반려식물과 통합 테스트의 중요성

> **복원일: 2026-10-29.** 사용자 직접 회고, 개인 Notion 활동 연대기, Drive `Post-EAT/GIF`·`GIF5`에 남은 2019년 Python/Arduino 및 사진 자료에 근거한다. **코드 보존과 제품 정상 동작, 팀 코드와 개인 저작 여부를 구분한다.** [기술·근거 원장](buddypot-2019-evidence-ledger.md) 참조.

## 한 줄 요약

**2019년 제5회 글로벌 이노베이터 페스타(GIF) 시기, Raspberry Pi 기반 반려식물 ‘버디팟’을 시도하며 센서·시리얼 통신·표정/음향 UI 관련 여러 코드를 작성했지만, 실제 제품은 기대만큼 안정적으로 동작하지 않았다.** 이 경험을 통해 **각 기능을 구현하는 것과 전체가 정상 작동하도록 검증하는 것은 다르며, 통합·사전 테스트가 중요하다**고 체감했다.

이력서에 넣을 때는 **완성/수상/출시한 스마트 화분**이나 **체계적인 자동 테스트를 이미 구축한 경험**으로 포장하지 않는다. 2026-10-29 사용자 회고의 핵심은 **실제 작동 미흡과 그로부터의 학습**이다.

## 맥락

- **시기:** 2019년 제5회 GIF 참가 무렵. Drive의 `Post-EAT/GIF`에는 **2019-11-02** 날짜로 된 현장 사진·Python 소스·이미지/음성 리소스가 남아 있다. 일부 사진에 **'5th GLOBAL INNOVATOR'** 행사 표기가 보인다. 날짜는 사진 파일명에 기초하므로 전체 개발 기간을 의미하지 않는다.
- **프로젝트 이름:** **버디팟(BuddyPot)** — 사용자 직접 회고 및 과거 개인 Notion 「나는 이때까지 뭐하고 살았나?」에서 2019년 GIF에 참가했던 Raspberry Pi 스마트 화분 프로젝트로 회고.
- **활동·팀 귀속(2026-10-29 직접 확인):** 버디팟은 **대학 1학년 때 친구와 함께 참여한 Post-EAT 창업동아리의 사람들과 진행한 프로젝트**였다. 다만 **음식점 리뷰·취향 SNS인 Post-EAT의 본 사업 구현물**과 **GIF 반려식물 버디팟**은 별도 아이템이다. **2021 제6회 GIF의 네모감성/‘엘리베이션’ 팀 서빙로봇 아이디어**와도 구분한다.
- **개인 기여:** 사용자가 직접 **'이것저것 코드는 짰다'**고 확인했지만 개별 파일의 작성자 기록은 없다. **코드 작업 참여**까지 확인 가능하며 아래 각 파일의 단독 저작·팀 전체 구현은 추정하지 않는다.

## 상황 → 문제 → 판단 → 조치 → 결과

### 1. 상황

Raspberry Pi를 사용해 식물을 **반려 대상처럼 표현하고 사용자와 상호작용하는 ‘버디팟’**을 개발하려 했다. 당시 자료에는 센서·시리얼 통신 실험 파일과 함께 **Pygame 눈·입 표정 이미지 3종, 애니메이션, 효과음**을 다루는 Python 파일이 다수 보존돼 있다.

### 2. 문제

여러 개별 기능을 코딩했지만 **당시 시제품은 기대한 만큼 잘 작동하지 않았다**는 것이 2026-10-29의 본인 직접 회고다. 구체적으로 무슨 센서가 언제 실패했는지, 어떤 증상이 재현됐는지에 관한 원본 시험 결과는 없다.

다만 보존된 구조는 통합의 미완성을 이해하는 데 도움이 된다. `GIF5/serial/test.py`와 Arduino `GIF5/sense/sense.ino`에는 서로 호응하는 센서 요청·응답 코드가 있지만, `GIF5/pygameTest/main.py`에는 **센서 입력을 화면 상태로 매핑하는 코드가 없고** `emotion = next_emotion`도 주석 처리돼 있어 **표정 변화를 센서 이벤트에 연결하지 않는다**. 다른 `GIF/main.py`에는 센서 관련 시리얼 부분이 주석 처리돼 있고 기본 표정 상태가 고정되는 구조다.

이 차이는 **보존된 버전들의 정적 코드 상태**이며 *최종 발표 파일이 이것이었다* 또는 *실패 원인이 이 한 곳이었다*고 단정하는 자료는 아니다.

### 3. 판단

프로토타입의 기능 구성은 **센서 상태를 읽고, 상태에 따라 반려식물의 감정을 표정·음향으로 표현하는 흐름**으로 해석할 수 있다. 입력/표현을 별도 실험한 뒤 하나로 연결해야 하는 구조였다. 이는 **코드에서 추론한 설계 의도**이며, 당시 사용자가 이 설계를 단독으로 결정했다는 근거는 없다.

**사후 교훈(사용자 회고):** 개별 모듈을 많이 만드는 것만으로 완성도를 보장할 수 없고, **모듈 간 연동과 실제 환경의 반복 테스트**가 필요하다. 다만 이후 이 프로젝트에서 테스트 계획을 수립하거나 자동 테스트를 도입했다는 증거는 없다.

### 4. 조치 — 남아 있는 코드에서 확인되는 시도

| 기술 작업군 | 보존 소스의 구체적 사실 | 서술 경계 |
|---|---|---|
| **Raspberry Pi 표정 UI** | `main.py`에서 Pygame **normal/smile/angry 3종**, 눈·입 각각 4프레임 이미지 및 상태별 효과음, fullscreen 루프 구현 | 화면·애니메이션 **코드 존재** ≠ 센서와 연결된 완성 제품 |
| **Arduino 센서 입출력** | `sense.ino`에서 **CDS 조도(A0)**, **IR 디지털(2번)**를 읽어 시리얼 명령 **B/D**에 대해 T/F 출력 | 초음파·온습도 등 다른 실험 파일과 **최종 하나의 회로**라는 증거 없음 |
| **직렬 통신 시험** | `test.py`가 `/dev/ttyACM*` 또는 `/dev/ttyUSB*`를 탐색하고 `9600bps`, **B/D 요청 → T/F 응답**을 출력 | 시험 코드가 있어도 안정적 통합 통신 성공을 뜻하지 않음 |
| **센서별 독립 시험** | `readDHT.py` 온습도(DHT11), `ADC0832.py`와 `analogRead.py` 아날로그 입력, `readUSD.py`·`UltraSonicDistance.py` 초음파 거리 읽기 시도 | **폴더 내 실험 흔적**. 실제 최종 버디팟에 모두 장착/사용했다고 주장하지 않음 |
| **표정·오디오 시도** | `pygame_1/2/3.py`, `animate.py`, `playsound.py` 등이 Pygame 화면·이미지·애니메이션·MP3 재생 동작을 나눠 시험 | 개별 코드의 실행 성공·실물 최종 채택 여부 및 파일별 개인 저자 미확정 |

### 5. 결과

- **산출물:** Raspberry Pi 기반 반려식물 시제품을 만들고자 한 경험, 센서/시리얼/표정·효과음 관련 **다수 소스·이미지·음향 자료** 보존, 2019년 제5회 GIF 행사 현장 사진 보존.
- **동작 수준:** **여러 코드를 작성했지만 실제 동작이 좋지 않았음**(본인 회고). 정량 성공률·장애 횟수·최종 센서 연결 상태는 확인되지 않았다.
- **성과의 핵심:** **작은 기능들의 구현 결과와 실제 사용자 앞에서 전체 제품이 동작하는지는 별개**라는 점을 체감했다. 이 경험은 ‘테스트의 중요성을 알게 된 실패·학습 사례’이지 **테스트 자동화 구축 성과**는 아니다.
- **수상/배포:** 버디팟이 상을 받거나 판매·출시·운영되었다는 근거 없음. 특히 **2021년 KT 트랙 대상**과 혼동하지 않는다.

## 이력서/면접용 문장

> **버디팟 — Raspberry Pi 반려식물 시제품 (2019 GIF 메이커톤)**. 센서 상태를 읽고 화면의 표정·소리로 반응하도록 하는 프로토타입을 시도하며 Python/Raspberry Pi·Arduino 관련 코드를 작성했습니다. 그러나 여러 기능을 개별적으로 구현했음에도 **통합 동작의 안정성이 부족해 기대대로 작동하지 않았습니다**. 이 경험을 통해 **개별 기능 테스트뿐 아니라 모듈 간 연동 검증과 실제 시연 환경의 사전 테스트가 중요하다**는 점을 체감했습니다. *(구체적 개인 작성 파일·실제 최종 회로/동작 성능은 확인 중.)*

**사용 권장 상황:** 실패 경험·기술적 학습·임베디드 HW/SW 통합과 검증의 중요성. **메인 포트폴리오에서 성공적 제품 제작 사례로 배치하기보다 성장 서사의 초기 사례**로 사용한다.

4. 이후 프로젝트에서 **이 경험을 계기로 테스트 방식을 실제 어떻게 바꿨는지**는 별도 프로젝트의 증거로 확인한 뒤 연결. 단순 시간 순서만으로 원인·성과를 만들어내지 않는다.
