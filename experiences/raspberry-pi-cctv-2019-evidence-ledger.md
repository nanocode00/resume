## 1. 프로젝트 목표가 어떻게 달라졌는가

- **제안서:** Raspberry Pi 카메라·Wi-Fi·Python, PIR와 카카오톡 챗봇을 사용해 스마트폰으로 집 안 상황을 확인하는 CCTV가 목적. 초기 **실시간 확인** 목표는 **팀 전체 목표**이지 최종 구현 완료 증거가 아니다.
- **1차 중간 발표:** **본인 = 파일 저장용 Python 코드 완료**, 다른 팀원이 카메라 테스트·OS 설치·챗봇 작업. 'PIR' 등 초기 작업 분담은 이 시점에 재배정되었다.
- **2차 중간 발표:** **본인 = 네트워크와 카메라 연결 완료**, 발표에서는 '실시간 영상 확인 코드 작성'으로 기재. 다른 사람들은 카카오 I 오픈빌더, 서보, PIR 기능을 담당했다.
- **최종 발표:** 영상인식은 **'기술적, 시간적 문제로 구현 불가'**로 명시. 본인 최종 역할이 **'저장된 동영상을 보기 위한 웹서버 구축'**으로 기재되고 **완료**로 표시. PIR 센서–영상 녹화 연결은 별도 팀원, 챗봇 영상 확인과 저장 영상 다운로드도 별도 팀원에 할당됨.
- **중간/최종 발표 간 차이:** 프로젝트의 목표·역할은 단계별로 바뀌었다. 변경 결정의 주체, 중도 포기한 영상인식의 구체 기법, 실제 원인 로그, 일정 효과를 **추정하지 않는다**.

## 2. 정적 소스 대조

### 웹 UI : `index.html`

원본 파일은 다음 구조를 가진다.
- 브라우저 영상 표시: `<video src="video.mp4" loop controls width="80%" height="80%"></video>`
- 파일 내려받기: `<a href="video.mp4" download="video.mp4">다운로드</a>`
- **동일한 고정 파일명** `video.mp4`를 대상으로 함.

**해석:** 저장 MP4를 브라우저에서 재생할 수 있도록 하려던 최소 웹 화면. 이것만으로 Live stream/WebRTC·사용자 인증·클라우드 배포가 있었다고 추론할 수 없다. HTML 파일에 다운로드 링크가 있는 점만으로 다운로드 기능 구현을 본인 실적으로 귀속할 수 없다. 최종 발표에서는 다운로드 기능을 **다른 팀원**이 담당했다고 명시했다.

### 팀 통합 촬영 : `cctv.py`

보존된 Python 59줄의 대표 흐름:
- `RPi.GPIO`, `picamera`, `os`, `shutil` 사용
- PIR 입력 GPIO BCM 4, 최근 상태 배열 `ary` 7칸, 루프당 `time.sleep(0.2)`, **7칸 전부 1이면** 녹화 트리거
- `getnum()`이 `/home/pi/Desktop/videos/num.txt`의 일련번호를 읽고 증가시킴
- `record()`의 `camera.start_recording()`과 `time.sleep(30)`로 **30초 녹화**
- `MP4Box -add`로 H.264→MP4, `shutil.copy(..., "/var/www/html/video.mp4")`로 **서버에 노출되는 고정 이름** 최신 파일을 갱신
- 저장 폴더 내 원본 이름은 `videoN.mp4`, 웹용 표시 파일은 `video.mp4`.

**해석 경계:** 이는 **정적 코드 경로**로, 실제 PIR 입력 품질, 동시 사용자 요청, 실시간 지연, 무한 반복 안정성, MP4Box 실패 예외 처리, 권한/보안, 마지막 파일의 클라이언트 캐시 문제 등을 검증한 것은 아니다. **최종 발표의 담당자 배분에 따라 이 통합 스크립트를 본인 개인 코드로 사용하지 않는다.**

### 촬영 시험 : `video_record.py` / `video_record_2.py`

- `video_record.py`: `picamera`로 **10초 H.264 녹화** 후 MP4Box로 MP4 생성, H.264 삭제.
- `video_record_2.py`: 파일 카운터 증가, 10초 녹화 후 MP4 변환, `/var/www/html/videoN.mp4`으로 복사; 마지막 `shutil.copy` 동일 구문이 **두 번** 들어 있다.
- `capture.py`: 카운터로 `imageN.jpg` 생성. `PIR.py`: GPIO 4 읽기 테스트.
- 해당 코드들은 **폴더에 존재한다**는 증거이며 전체 작성자가 본인이라는 근거는 아니다.

### 서버 정황

`Apache2 Debian Default Page_ It works.html`이라는 저장 파일은 Apache 설치 기본 페이지를 담고 있다. `/var/www/html/video.mp4` 경로와 `index.html`의 상대 경로가 맞물리므로 **Apache를 사용한 정적 파일 서빙 구성**과 부합한다. 그러나 정확한 설치·실행 로그가 없으므로 HTTP 설정/포트·방화벽·공인 접근·스마트폰 사용 성공을 단정할 수 없다.

## 4. 날짜·기타 문서 간 충돌

- 최종 발표에는 **10/30·11/10·11/13·11/21·11/25·11/30·12/1·12/2** 팀 회의가 적혀 있다. 일부 다른 복사본은 미완성 템플릿 제목('머신러닝을 통한 신조어 확산 기반 소셜네트워크 지도')이 남아 있지만 **본문 CCTV가 일관**하므로 해당 템플릿 제목을 프로젝트명으로 사용하지 않는다.
- **2026-10-29 고교 자료 추가 발굴:** 본인은 **‘찰칵!’ 도난 방지 시스템**의 고교 4인 팀에서 **팀장·프로그래머·엔지니어**로 발표자료에 기록되어 있다. **초음파 문 열림/거리 변화 감지 → Raspberry Pi 사진 촬영** 모형을 제작했고, 배선 길이 때문에 Bluetooth를 고려했으며 **실제 교실에는 설치하지 않았음**을 회고했다. 관련 당시 발표·Python·Arduino 파일은 **대학 2019년 프로젝트의 `8조` 자료와 분리된 별도의 Drive 폴더**에서 발견됐다. [고교 경험 문서](highschool-theft-prevention-camera.md) · [고교 증거 원장](highschool-theft-prevention-evidence-ledger.md) 참조. 학교 수상은 기억만 있어 검증 전이다. **서로 다른 두 CCTV를 병합하거나 소스/성과를 교차 귀속하지 않는다.**
- `raspberry pi files`의 다른 Python, Bluetooth/USB 등 파일은 CCTV와 관계가 불명확한 실험/연습 파일일 수 있다. **폴더 전체 파일을 모두 본인이 작성한 CCTV 구성요소로 합산하지 않는다.**
