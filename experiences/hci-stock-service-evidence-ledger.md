## 3. 개인 커밋 기여 상세 — HC-01 / HC-02

### HC-01 — ORM 데이터 모델과 적재

**근거:** [2660f755](https://github.com/nanocode00/hci/commit/2660f755f403fab6f6b2381541cd699d24c8f02d)의 **db.py** 신규 305줄.

원본 개인 커밋이 추가한 SQLAlchemy 엔터티는 5개.

1. **stocks:** 코드(unique), 이름, 기업정보 URL, 현재가격
2. **brokers:** 증권사 이름(unique)
3. **authors:** 애널리스트 이름(unique)
4. **ratings:** Buy/Sell/Hold/None 코드와 설명
5. **reports:** 날짜, 제목, 목표가, 기준가격, 기대수익률, 첨부 URL과 stock/broker/author/rating FK

**구체적 구현:** SQLite engine/session, relationships/back_populates, 테이블 생성·기본 rating 코드 삽입, CSV DictReader 및 날짜·정수·실수 변환, 평가의견 동의어 정규화, 종목·증권사·작성자 캐시와 기존 DB 조회, 새로운 리포트 삽입.

**정확한 경계:** 테이블 분리와 FK는 **정규화 지향 구현**이지만 이 자체로 3NF의 모든 조건을 수학적으로 검증한 것은 아니다. 원본 개인 커밋의 CSV 적재에는 리포트 attachment_url에 대한 중복 방지 조건이 있음을 별도로 확인하지 못했으므로 **리포트 자체의 완전한 중복 방지**를 주장하지 않는다. 현재 main의 db.py는 후속 팀원 수정으로 구조가 달라져 있으므로 **현재 main 기능 전체를 개인 초판 구현으로 소급하지 않는다**.

**5단계 연결:** 상황(반복 속성이 있는 증권 리포트) → 문제(검색/관계 관리) → 판단(엔터티 분리) → 조치(5테이블+CSV 적재) → 결과(원본 코드 추가 및 조회 예시). 개선 전후 DB 속도, 중복 제거 건수·품질 계측은 부재.

### HC-02 — 검색·조인 쿼리

**근거:** 같은 [2660f755](https://github.com/nanocode00/hci/commit/2660f755f403fab6f6b2381541cd699d24c8f02d)의 **query.py** 신규 108줄.

- **show_all_reports:** 최신 작성일/ID 기준 전체 출력
- **search_by_stock_name:** Stock 이름 LIKE 부분 검색
- **search_by_broker:** Broker 이름 LIKE 부분 검색
- **search_by_author:** Author 이름 LIKE 부분 검색
- **search_by_rating:** Report.rating_code와 코드 필터
- 공통 **print_report**: 작성일·종목·가격·평가의견·증권사·애널리스트·첨부 URL 출력

관련 [초기 커밋](https://github.com/nanocode00/hci/commit/2660f755f403fab6f6b2381541cd699d24c8f02d)에는 **all_reports.txt**, **search_author_전유진.txt**, **search_org_메리츠.txt**, **search_stock_LG화학.txt**라는 조회 결과 파일도 있다. 출력 아티팩트가 생겼다는 정황은 존재하지만 모든 데이터의 최신성·정확성/대규모 성능/자동화 테스트 증명은 아니다.

**개인 작성 범위의 수량:** 이 커밋은 GitHub에서 **총 +7,037줄**로 표시되지만, 그중 **db.py 305줄 + query.py 108줄 = 413줄**만 이 두 소스 파일이고, 나머지 대다수는 생성·조회 출력 텍스트다. **7천 줄 프로그램을 직접 구현했다고 기재하지 않는다.**

**5단계 연결:** 상황(여러 검색 기준) → 문제(리포트와 기관/작성자 관계) → 판단(ORM 관계 조회·정렬) → 조치(4개 조건검색+전체조회) → 결과(쿼리 코드·예시 출력). 실제 사용성 점수 향상을 이 개인 함수의 직접 효과로 연결하는 것은 불가.

### 전체 리포지토리 구현과 개인 기여 분리

현 main에는 **FastAPI/Jinja2** 서버와 /data.html 검색, /statistic.html 집계, 리포트 **scraper.py**, **get_pdf.py**, **services.py**, **pipeline.py**, Render 배포 안내가 남아 있다. 이는 **팀 프로젝트의 구현 범위**로 설명한다.

- main의 **main.py** route에는 Stock/Broker/Author를 join하고 부분검색해 HTML 출력하는 코드가 있다. 이것은 **query.py의 CLI 출력 함수를 그대로 호출하는 구조가 아니다**.
- **scraper.py**는 한경 컨센서스에서 기업 리포트 데이터를 스크래핑하고 **save_reports**를 호출한다. 이 파일은 현재 본인 author 직접 커밋 목록에 없다.
- **services.py**는 FinanceDataReader로 주가를 조회하는 함수를 정의한다. 팀 발표는 서버 시작 때 갱신한다고 설명한다. 이 기능을 직접 구현했다고 주장할 근거 없음.
- **templates/**의 HTML, **static/**, **tmp/**의 디자인·외부 템플릿/라이브러리 파일은 개인 단독 UI 개발 분량으로 귀속하지 않는다.

## 4. 팀 사용자 평가 — 원본 데이터 재계산

### 조사 기간·구조

**hci_interview.csv**를 UTF-8-sig CSV로 읽어 확인: header 1행 + **응답 18행**, 총 **23개 컬럼**, 원본 일시 분포 **2025-12-09 / 2025-12-11(KST)**. 동일 응답자가 **A=한경 컨센서스 / B=프로젝트** 각각 직관성·정보 획득 과정·만족도·사용 의향을 답한 짝 데이터다. 평가 항목의 척도는 1~5점이며, 투자 경험 응답 Yes/No는 **9명/9명**이다.

재계산 방식: 동일 응답의 A/B 두 점수를 1:1 대응시켜 각각 평균과 차이를 산출했다. Python/Numpy/SciPy로 대응표본 t-검정, 차이에 대한 Shapiro-Wilk 검정, 사후 보조 분석 Wilcoxon signed-rank를 실행. **후자는 2026년 사후 보조 분석(D)이지 당시 제출 결과 아님**.

| 변수 | CSV A 평균 | CSV B 평균 | B-A | 원본 t(df=17), 양측 p | Shapiro-Wilk p(차이) |
|---|---:|---:|---:|---|---:|
| Q1 정보 구조 직관성 | 2.7222 | 4.2778 | +1.5556 | -4.93165, p=0.0001265 | 0.01925 |
| Q2 정보 탐색 자연스러움 | 2.7778 | 4.4444 | +1.6667 | -5.95119, p=0.0000158 | 0.27557 |
| Q3 전반적 만족도 | 2.4444 | 4.4444 | +2.0000 | -6.86126, p=0.00000276 | 0.02922 |

원본 PDF의 반올림 결과 **t=-4.93/-5.95/-6.86, p<.001**, N=18와 원본 재계산이 부합한다. Shapiro-Wilk **Q1/Q3에서 p<.05**이므로 t-검정 가정을 조심해서 해석해야 한다. 사후 검토로 별도 Wilcoxon 양측검정에서도 Q1 p≈0.00196, Q2 p≈0.000504, Q3 p≈0.000546으로 방향은 유지됐으나 **비정규 데이터·동점 처리·다중 검정·작은 표본에 대한 해석 제한은 계속 유효**하다.

| UX·웹 배포 | FastAPI/Jinja2 HTML 및 Render URL README에 존재, 최종 발표에 데모 수록 | 팀 차원의 웹 구현·발표는 확인. 현재 라이브 정상 가동, 운영/보안/품질 미검증 |
| 로그인/회원가입 | HTML 템플릿 라우트는 있지만 인증 backend 동작은 확인 불가 | 인증 시스템 구현 주장 금지 |
| 서드파티 UI | tmp/sneat-1.0.0 등 배포용 프런트엔드 템플릿과 vendor assets | 개인 신규 개발량에서 제외 |
| 유저 스터디 인과 | B 점수 상승과 기획 방향은 일치 | 개인 DB 구현만의 인과효과, 객관적 검색시간 단축을 주장하지 않음 |

**버전 경계:** 2025-11-24 개인 커밋의 원본 **db.py**는 현재 main의 **db.py**와 같지 않다. 이후 DB 적재 API·중복 처리·후속 요약 컬럼 등이 수정되었다. 직접 개인 기여 확인은 **해당 SHA의 신규 db.py / query.py**로 한정한다.

## 6. 제출용 사용 원칙 및 잔여 사항

**개인 역량 대표:** “SQLite/SQLAlchemy 다섯 테이블, CSV 입력 정규화·적재, 종목/증권사/애널리스트/의견 조건 검색 쿼리 직접 구현”. 프로젝트의 데이터 구조를 직접 기획·설계/구현한 기술 사례로 활용할 수 있다.

**팀 성과 참고:** “기존 한경 컨센서스와의 18명 사용자 조사에서 정보 직관성 2.72→4.28, 정보 탐색 자연스러움 2.78→4.44, 만족도 2.44→4.44를 기록”은 **팀 결과와 설문 한계**를 함께 밝힌다.

**남은 미확정 (종료 가능):** 개별 설문 모집/분석과 UI 작업의 정확한 개인 분담; 운영 DB의 실제 건수/기대수익률 계산; PDF Gemini 생성 코드의 보존 경로; 서비스 가동/데모 재현; 정확한 UI 자산 최초 저자; 실제 과거 목표가 적중률 기능 존재 여부. 확인 전까지 경력 성과에 추가하지 않는다.

**원본 파일을 공개 GitHub에 올리지 않는 이유:** 설문 원본의 각 응답과 timestamp는 연결 계정의 자료이며 개인정보·참가자 프라이버시가 문제될 수 있다. 표·집계 통계만 공개하고, 필요시 당사자 접근 가능한 Drive 원본에서 사후 재현한다. 전체 웹 복제품이나 상업적 데이터 무단 배포도 수행하지 않는다.

> 이 원장은 [canonical 경험 서사](hci-stock-service.md)의 출처·공로 구분 근거다. 다른 프로젝트처럼 **상황 → 문제 → 판단 → 조치 → 결과**를 설명하는 데 필요한 사실은 확보되었고, 미확정 항목의 해소는 선택적인 보강 작업이다.
