# 고교 Arduino 드론 — 증거·예제 코드 저작·Paperware 연결 원장

> **2026-10-29 직접 회고**와 개인 Drive 소스, 기존 `experiences/nemogamsung-early-maker-evidence.md`·`experiences/paperware.md`의 2026-10-24 직접 확인 기록을 대조한 문서. **Arduino 교재 키트**, **이후 Paperware 카드보드 micro:bit 드론**, **외부 제공 예제 코드**를 혼동하지 않는다.

## 2. 출처 구분: 코드에 구현돼 있는 것과 사용자가 만든 것

- `_10ypr.ino`에 **IMU 가속도/자이로를 읽고 자세 각도를 추정하는 코드**가 존재함.
- `_15dualpid.ino`·`_16drone_remote.ino`·`drone.ino`에는 **PID → 모터 값 계산 → 제어 출력** 코드 경로가 존재함.
- `drone.ino`는 사용자가 **책에서 제공받은 코드**임을 이미 확인했다. 단계별 파일도 책·키트 실습 맥락의 **예제 파일로 취급**하고, **사용자가 독자 개발했다고 추론하지 않는다**.
- **직접 기체를 조립하고 실행해 본 경험**은 C1으로 확인된다. 어떤 프로그램을 어떤 값으로 변경해 실행했는지, 모터별 측정·실패 원인·로그·비행 안정성·최대 비행 시간 등은 **A1~A7에서 확인되지 않는다**.
- 교재 예제를 **읽고 실행해 원리를 익힌 학습**과 **새로 설계한 제어 알고리즘의 개인 구현**은 별개다.

## 3. 후속 Paperware와 연결하는 올바른 방식

`고교 Arduino 교재·키트 → 드론 센서/자세/모터 구동 원리 학습 → 후속 카드보드·micro:bit 드론 창작 시도`

**사용자 2026-10-29 직접 회고**가 위의 **경험적 기반** 관계를 명시적으로 확인한다. 다음까지 주장하지는 않는다.

- 특정 Arduino 스케치를 Paperware용 micro:bit 기체에 포팅했다는 사실.
- 기존 도서 제공 PID 구현을 사용자 독자 알고리즘으로 개량했다는 사실.
- 교재 드론에서 이륙 실패했거나, Paperware 드론에서 정상 비행했다는 주장.
- Paperware 제작의 모든 HW·SW 개인 단독 저작.

현재 근거상 **Paperware의 `controller.py` 버튼/가속도·라디오 송신 구현**과 **후속 카드보드 기체의 이륙 실패(하중 대비 추진력 부족)**가 유효한 별도 결과다. 이 **실패 원인**은 이후 사용자 회고로 확인된 Paperware 기체에 한정한다.

## 4. 이력서용 검증된 구분

| 진술 | 판정 | 근거 |
|---|---|---|
| 고교 때 Arduino 드론 교재·키트 구매 및 실제 조립·실험 | **사용자 직접 확인** | C1 |
| 드론의 IMU/자세제어/PID/모터 원리 이해 | **실습 회고 + 코드의 학습 대상 구조** | C1, A3~A6 |
| 단계별 예제 폴더와 `drone.ino` 소스 보존 | **코드/메타데이터 확인** | A1~A6 |
| 해당 PID·보완필터·MSP·모터 스케치를 모두 직접 창작 | **불가** | C2(도서 제공), 작성 로그 미확인 |
| 교재 키트를 안정적으로 자유 비행·성능 개선 | **미검증** | 조종/성능 원본 없음 |
| 고교 경험이 후속 Paperware 드론의 기반 | **직접 확인** | C1 |
| Paperware에서 micro:bit 컨트롤러 직접 작성·기체 제작 후 이륙 실패 | **별도 경험으로 허용** | C2, P1 |
| Paperware의 추력 부족을 고교 Arduino 키트의 결과로 합침 | **금지** | 서로 다른 제작 맥락 |

## 5. 정리 상태

이 경험은 **학습·성장 및 후속 프로젝트 준비 단계**로 복원 완료. **실물 비행 원본과 직접 수정한 코드는 추가 확인이 있으면 보강**할 수 있으나, 지금도 '교재·키트에서 익힌 원리를 Paperware 자체 시도에 활용했다'는 경험 흐름을 서술하는 데 필요한 근거가 충분하다.
