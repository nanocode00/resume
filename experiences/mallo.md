# Mallo — Voice-first Kiosk

## 한 줄 요약

고령 사용자를 주요 대상으로 음성으로 주문 과정을 보조하는 키오스크를 기획하고, 팀장으로서 TTS 파인튜닝, AI 모델 비교, UI/UX 개선과 전체 AI 파이프라인 검증을 진행한 프로젝트.

## 기간 및 역할

- 2026.06 ~ 진행
- 역할: 팀장
- 주요 담당: TTS 파인튜닝, AI 모델 비교, 경쟁사 분석, UI 개선 방향 수립

## 문제 정의

키오스크 사용이 익숙하지 않은 사용자가 복잡한 화면 탐색 대신 음성으로 주문을 진행하고, 필요한 경우 천천히 듣기나 다시 듣기, 직원 호출 같은 접근성 기능을 사용할 수 있도록 하는 것을 목표로 했습니다.

## 전체 파이프라인

`Mic → VAD → STT → NLU → Validator → Order Engine → Adaptive TTS → TTS`

초기 구성:

- STT: Whisper Medium 또는 Mock
- NLU: Local LLM
- TTS: MeloTTS, Qwen3-TTS 또는 Mock
- Sidecar 기반 STT/NLU/TTS 분리

## TTS 파인튜닝

AI Hub의 친절체 데이터를 활용해 MeloTTS와 Qwen3-TTS 파인튜닝을 진행했습니다.

초기에는 출력이 정상적인 한국어가 아닌 문제가 있었지만 학습 설정과 데이터 구성을 점검해 정상 발화가 가능하도록 수정했습니다.

모델별 생성 시간과 표현력을 비교했고, MeloTTS는 빠른 반면 감정 표현 측면에서 제한이 있음을 확인했습니다.

## UI/UX 개선

음성 기능만 연결하는 것으로 충분하지 않아 주문 화면 자체의 사용 흐름도 함께 수정했습니다.

- Voice Overlay 구성
- 접근성 footer를 2×2 구조로 정리
- 음성 속도 단계 순환 기능
- 다시 듣기
- 천천히 듣기
- 직원 호출
- ORDER / REVIEW / PAYMENT 화면 레이아웃 개선

## 런타임 및 배포

- STT, NLU, TTS를 독립 sidecar로 구성
- `/health`에서 각 모듈 ready 상태와 warm-up 상태 확인
- Vercel UI와 Local FastAPI 런타임을 연결
- 런타임 모델과 원본 학습 데이터를 분리해 배포 크기를 정리
- STT/TTS showcase를 별도로 제작해 모델 결과를 비교할 수 있도록 구성

## 검증 경험

- STT와 TTS를 같은 GPU에서 함께 실행하며 VRAM 사용량 확인
- 직접 녹음한 한국어 발화로 STT 결과 확인
- TTS baseline과 fine-tuned checkpoint 및 속도 단계별 결과 비교
- 기능 구현뿐 아니라 모델 지연, GPU 자원, 접근성 UI까지 함께 확인
